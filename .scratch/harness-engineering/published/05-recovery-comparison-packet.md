## Parent

[Spec: trustworthy offline engineering evidence](https://github.com/matheusht/redteam-harness/issues/106)

## What to build

A reviewer can inspect concrete harmless document cases, expected trace accounts and a pinned protocol that could distinguish recovery-interface requirements before a framework is selected.

## Acceptance criteria

- [ ] Provide document versions, a late correction, a recorded-but-unsupplied result, cooperative pause and simulated loss after an artifact write without its receipt. Use synthetic text and metadata only.
- [ ] Define the default observation point as arguments received by a scripted adapter with declared client-managed history. Separate local admission, invocation and unobserved provider acceptance.
- [ ] Expected accounts retain source revision, unfinished work, error/termination flags, uncertain effects and measured/unknown usage. Saved conversation state must not imply exactly-once artifact work.
- [ ] Keep persisted no-summary rollover as a separately identified optional diagnostic. Do not change the required contract after inspecting candidate outcomes.
- [ ] Pin the candidate source versions and distinguish inspected tests, executed checks, unsupported interfaces and unknown behavior. Include the present baseline and a supported candidate; deeper ownership remains conditional on an unsupported required contract.
- [ ] State total resource ceilings, matched case ordering, grading isolation, allowed data and maintenance/compatibility accounting. An unavailable representative launch configuration prevents an ordinary-session claim, not completion of the synthetic packet.
- [ ] Validate complete and deliberately incomplete illustrative accounts through the shared offline study-report boundary. Mark them synthetic; no candidate receives a passing execution result merely from a source citation or fabricated trace.
- [ ] Include an explicit run-readiness checklist and stop/rejection criteria. Leave execution unstarted when effective configuration or run authorization is absent.
- [ ] Build no provider adapter, runtime, dispatcher, persistence backend or custom model loop. Do not modify native-client settings or execute a provider call.
