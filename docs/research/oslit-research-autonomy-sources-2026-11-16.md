## The supplied POC 2026 presentation

Kyeongmin Kim and Insu Yun's *1 Man, 1 Month, 45 Bugs: Scaling AI Bug Hunting to $100K+ in Bounties* describes candidate discovery, verification and human adjudication. Its strongest lesson for this plan is the recovery of rejected or blocked candidates through a changed configuration, protocol sequence, multi-file interaction or virtual substitute for hardware (slides 64–65). Those cases support retaining the scope of a negative result and investigating what would change it.

The headline counts do not establish the value of each stage. The authors report no ablation and did not independently revalidate candidates removed during initial analysis (slides 57–58). In the later verification sample, the confusion matrix contains 41 true positives, 24 false positives, four false negatives and 145 negatives. Four divided by 149 is the proportion of system-negative cases later found positive; four divided by the 45 human-confirmed positives is about 8.9%. Neither measures recall over the initially filtered candidates or undiscovered vulnerabilities. Some blocked cases remain epistemically different from disproven hypotheses.

The design consequence is to distinguish invalid evidence, an untested claim, a blocked measurement and a demonstrated negative. Do not copy the presentation's number of judges, interpret declining yield as exhaustive coverage, or turn a researcher's successful recovery suggestion into a mandatory universal sequence.

## Persistence and usable memory

[Anthropic's components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) includes a case where a false memory sustained the wrong strategy; consulting the underlying trace enabled correction. Its document experiments also vary in how much benefit compression provides. This supports recoverable originals and selective working context. Repeated encouragement, more summaries or a larger archive alone are weak substitutes for checking the premise of the next action.

Its database-task experiment also found that restricting memory to failures reduced the benefit for the stronger tested models. This supports letting agents select useful observations, with a clear purpose for memory rather than a compulsory recording template.

[ExpVoyager](https://arxiv.org/html/2609.32630v1) compares structured experience access with chronological files and terminal search, but its small-model setting and component ablations do not establish necessity for an optimized frontier native agent at equal total cost. Its failures include finding the right information and still misapplying its order or conditions. [ReasoningBank](https://arxiv.org/html/2509.25140v1) similarly provides bounded evidence for useful failed experiences and selective retrieval; it does not supply an iterative native-file-search baseline. Together these sources challenge both extremes: assuming an archive guarantees reasoning, and assuming a dedicated memory architecture is already justified.

The first comparison should locate the failing step: a fact was never available, remained undiscovered, lost its meaning during summarization, was misapplied, or required a new measurement. Those are different problems.

## Retrieval is assistance, not a truth oracle

[Vul-RAG](https://arxiv.org/html/2406.11147v3) is useful because its error analysis includes false positives caused by alternative valid fixes, missing analogues and vague or irrelevant knowledge. A retrieved historical patch is not the only valid way to prevent a dangerous state. Its function-classification evaluation does not establish dynamic vulnerability reproduction or improvement over a capable agent doing iterative research. The released code also needs a pinned version: its ranking and call patterns are not identical to every description in the paper.

[Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval) studies fixed-query chunk retrieval. Its [appendix](https://assets.anthropic.com/m/1632cded0a125333/original/Contextual-Retrieval-Appendix-2.pdf) illustrates how document identity and surrounding context help interpret a passage; it does not show that native iterative search failed on those examples. The [public notebook](https://github.com/anthropics/claude-cookbooks/blob/785d7a06457b3413727f386b9c470083feb23c49/capabilities/contextual-embeddings/guide.ipynb) measures retrieved gold-chunk coverage, not the quality of a subsequent investigation. Index enrichment, ranking and additional model work must be separated when comparing approaches.

Start with a populated, accessible corpus, useful titles and full source access. Compare a ranked retriever only when observed search failures warrant it, with the same descriptions and sources available to native search. No retrieved match means no match was found; it does not establish the absence of a vulnerability.

The quoted social-media ranking of frontier models, retrieval and fine-tuning is a practitioner claim without a supplied reproducible experiment. It motivates a hypothesis. It does not settle our model, retrieval or training strategy.

[OSV's withdrawn-record behavior](https://google.github.io/osv.dev/faq/#how-does-osvdev-handle-withdrawn-records) offers a useful design precedent: withdrawn entries leave normal query results but remain available by identifier and in exports, with their status visible. For OSLit, this suggests separating a current recommendation from retained historical material. It does not establish that a technique transfers or prescribe a new evaluation service.

## Domain procedures and transferable learning

The original [conference clip](https://x.com/unpromptedconf/status/2121372527851458628) and [Anna Groza/Bruce Dang deck](https://github.com/pwnlambda/talks/blob/main/unprompted_0clicks.pdf), slide 19, show a prompt invoking `xzone_malloc` and prior research. The clip describes earlier instruction work and later human verification. It does not expose the skill's content, isolate its contribution or demonstrate a specific shortcut prevented by AGENTS.md. The highlighted three-hour interval excludes preparation and later verification. The defensible lesson is that useful expert context can be part of the workflow; the packaging itself is not causal proof.

[ExpeL](https://arxiv.org/html/2308.10144v3) contrasts observed successes and failures and tests held-out tasks; model-written reflections do not invariably help. [Agent Workflow Memory](https://arxiv.org/html/2409.07429v1) describes incorrect workflows and failures when a workflow does not fit the current state. [Learning by Doing](https://arxiv.org/html/2611.01386v1) explicitly distinguishes reported outcomes from controlled estimates of a skill's causal benefit. These support independent transfer and counterexample checks, without requiring a separate evaluator service for each note.

A controlled negative can teach a useful diagnostic method. Replaying the same source task in another session is useful reproduction evidence, but is narrower than transfer to a changed implementation or condition. A different valid protection is a particularly useful counterexample to a technique learned from one historical fix.

[Demystifying Agent Skills](https://arxiv.org/html/2608.14036v1) makes that distinction concrete: its main design derives procedures from a task's earlier runs and reruns the selected tasks. It also compares against compact plans and workflow memories. Its headline advantage over workflow memory should not be read as the same advantage over an unassisted agent; the paired skill-versus-raw estimate is uncertain. This supports comparing the smallest useful form of prior experience, not assuming that `SKILL.md` is always better than an ordinary note.

## Chainability without a prescribed graph

The [Next.js postmortem](https://vercel.com/blog/postmortem-on-next-js-middleware-bypass) makes deployment and trust assumptions concrete. The [curl advisory discussion](https://github.com/curl/curl-www/pull/308) distinguishes a blocked memory consequence from a surviving constrained protocol effect. The [Nomad root-cause analysis](https://medium.com/nomad-xyz-blog/nomad-bridge-hack-root-cause-analysis-875ad2e5aacd) connects changed code semantics with persistent initialization state.

These cases motivate retaining conditional effects and testing actual transitions. They do not prove that a graph database, dependency schema or automated chain ranker would have found the issues. A smaller effect can remain relevant after a larger hypothesis fails; two individually observed effects do not automatically compose under the same state and authority.

## Let stronger models remove machinery

[OpenAI's Linux research](https://openai.com/index/a-thousand-fewer-paths-to-root/) reports a larger benefit from a technique layer for one model generation and a much smaller incremental gain for the next, leading the team to remove heavier orchestration. This is a bounded vendor result, not a rule that stronger models never need domain knowledge. It supports reevaluating removable aids while retaining evidence, source material and outcome checks.

The [harness workshop's comparison method](https://grahamhelton.github.io/harness-engineering-workshop-book/research-problems.html#how-we-will-approach-these-problems) preserves baseline strengths and ties. Its [skill chapter](https://grahamhelton.github.io/harness-engineering-workshop-book/harness-components/reusable-skills.html) distinguishes reusable instructions from tools that actually execute them. The plan's comparison asks whether the addition improves actual research decisions at a comparable total allowance. Skills invoked, documents retrieved and more polished reports are insufficient outcomes.

The durable specification should describe desired behavior and the checks that would falsify it. A stronger model may implement that specification more simply. Rewriting from prompts alone cannot establish that it preserved historical meaning, permission boundaries or research correctness.

## Existing reference content needs honest labels

The inspected repository already retains [fix-diff notes](https://github.com/matheusht/redteam-harness/blob/95e5e0f1c01817c54cd4e137b990f9c663f1e960/skills/oracles/references/ghsa-fix-diff-corpus.md), [disputed/rejected-CVE notes](https://github.com/matheusht/redteam-harness/blob/95e5e0f1c01817c54cd4e137b990f9c663f1e960/skills/oracles/references/rejected-disputed-cve-corpus.md) and [disclosed-chain notes](https://github.com/matheusht/redteam-harness/blob/95e5e0f1c01817c54cd4e137b990f9c663f1e960/skills/oracles/references/project-zero-zdi-chain-corpus.md). They contain useful searchable text and primary pointers, not every complete article or commit. Their directory name does not make them execution oracles.

The chain file illustrates a concrete quality issue: its introductory ProxyShell correction gives three stages, while the corresponding body still labels the middle stage as the final execution step and presents two stages. The original researcher's [ZDI writeup](https://www.thezdi.com/blog/2021/8/17/from-pwn2own-2021-a-new-attack-surface-on-microsoft-exchange-proxyshell) explicitly separates all three. Reusing these notes as historical references is reasonable; silently carrying their old verification labels into a recommended library is not. The known discrepancy can be corrected in a new retained version during packaging, without rewriting historical engagement evidence or requiring a fresh audit of every URL before any search.

### Campaign, public framework and deployment evidence

[PwnEscape](https://pwn.ai/blog/pwnescape) describes human-led security research using private Omega-Pwn, elements of OmegaClaw and model assistance. Its useful lesson is how a smaller observed effect survives a failed explanation and becomes useful when later work establishes the missing conditions. The technical outcome supports the research account; it does not isolate the contribution of a particular harness mechanism. The [partner account](https://bengoertzel.substack.com/p/pwnai-experiments-with-omega-finds), dated 15 October, also describes human-led work and an experimental system family. Public Omega code supplies concrete mechanisms to inspect, but does not fully specify the campaign.

The supplied repository URL now resolves to [singnet/Omega](https://github.com/singnet/Omega). This review pins its source to `ba185cd359d9fe231b904110b988af39fafa5014`, dated 12 November. The exact campaign revision and private Omega-Pwn additions were not located in the searched public materials. OSLit's comparison remains the inspected `95e5e0f1c01817c54cd4e137b990f9c663f1e960` implementation, separately from the later-approved autonomy plan.

The AGI 2026 chapter, [OmegaClaw: A Continually Operating Agentic Architecture Under Bounded Resources](https://doi.org/10.1007/978-3-032-33010-9_22), has a public abstract and an [operational evidence supplement](https://github.com/khellar/omegaclaw-evidence/blob/e55fc05a0b64e433e632e62528e999186fdf6177/README.md), also [archived on Zenodo](https://doi.org/10.5281/zenodo.20573331). The supplement reports one 91-day deployment, 5,473 messages and 24 human participants. It provides selected anchored excerpts of cross-session recall, persistent goals, mistakes and recovery attempts. This is operational evidence beyond an architecture description. It is not 91 days on one unattended security investigation, nor a matched estimate of the harness's benefit.

The [behavior records](https://github.com/khellar/omegaclaw-evidence/blob/e55fc05a0b64e433e632e62528e999186fdf6177/vectors_of_interest.md) include imperfect retrieval, a remembered backup after an operator-caused history wipe, rules that failed to fire and tested artifacts that were not running in the loop. The full transcript and memory dump are not public in this supplement. Its excerpted self-reports cannot all be independently reconstructed from the released subset. The frozen deployment prompt also differs from today's default.

The chapter's abstract separately reports controlled memory/ARC3 experiments and a multimodal case study. Its subscription-only full text was unavailable, and a bounded search did not locate an accessible author manuscript. Methods, baselines and scores therefore remain uninspected. Do not substitute this observational supplement, a separate mock benchmark repository or search-snippet scores for those controlled results.

### Simple capability taxonomy

Here, **present** means source-visible mechanics, not proven autonomous research quality. **Partial** names a missing part of the workflow. Neither public Omega source nor the inspected OSLit checks establishes superiority on long security investigations.

| Capability named in the article | OSLit now | What the comparison changes |
| --- | --- | --- |
| Longer research horizons | **Partial.** The runner continues after ordinary answers and renews worker authority. Some faults and internal session limits still end active progress. | Complete planned safe continuation and context recovery. A running loop alone is insufficient. |
| Persistent campaign state | **Present records; partial recovery.** Tasks, observations, evidence, reviews and usage survive in the journal. A fresh session can retain an old delivery cursor without receiving its earlier working context. | Restore useful orientation from existing records, including previously acknowledged material. No second authoritative memory store. |
| Parallel collaborative investigations | **Present.** Lead/specialist ownership, continued specialist sessions, shared publications/notices and fresh independent review exist. | Keep this controller. Broader native-helper support remains planned; an external-agent gateway is not required for collaboration. |
| Accumulation of hypotheses, failed experiments and evidence | **Present when recorded; partial behavioral continuity.** Publications and experiment records support correction/search. ### Concrete public mechanisms

**Continued opportunities to act.** Omega's [loop](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/src/loop.metta#L11-L139) defaults to a burst of 50 model turns after new input, followed by one scheduled turn every 600 seconds. It has no goal-completion predicate. Its [prompt](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/memory/prompt.txt#L1-L9) supplies goal direction, mandatory memory queries and a five-cycle thinking minimum. These instructions are not enforced measures of useful effort. Provider retries and continued scheduling help with some interruptions; they do not establish durable recovery of an interrupted action or automatic restart of a dead process. OSLit already owns continued invocation and reviewed closure, so another outer loop adds little.

**Persistent semantic lookup.** Omega's [memory tools](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/src/memory.metta#L29-L61) retain selected text in Chroma and retrieve semantically similar entries. This can find related ideas that use different words, a capability absent from OSLit's current substring board search. However, the [normal query bridge](https://github.com/patham9/petta_lib_chromadb/blob/218484875d5d1bfb217a9a03d3983dc1ed9d406c/lib_chromadb.py#L10-L84) returns timestamp/text without source identifiers, and [knowledge reindexing](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/src/rag.py#L268-L356) replaces old chunks. Preserve OSLit's planned source/version retention. Try semantic ranking if ordinary iterative search demonstrably misses useful material; retrieval relevance and correct use remain separate checks. The bridge was inspected at the separately pinned revision linked here; Omega [selects its moving `master` branch](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/Dockerfile#L48-L69), so the Omega commit alone does not fix this dependency.

**Procedures loaded during work.** The [workflow plugin](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/plugins/workflow/workflow.metta#L48-L116) refreshes a catalog, loads selected instructions/tools and unloads them. This supports the planned active knowledge-oracle path. The sample [research helpers](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/plugins/workflow/instructions/research-workflow/skill.metta#L68-L100) are narrower: `research-step` ignores its result/next arguments, and `research-checkpoint` sends a waiting message without establishing a paused state. Loading a procedure does not establish its execution or successful transfer. Reuse native file/helper delivery rather than importing this plugin runtime.

**Asynchronous delegation.** The optional [OpenClaw bridge](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/plugins/openclaw/openclaw.py#L85-L223) creates fresh external sessions and later collects replies. Its [documented restart limit](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/plugins/openclaw/README.md#L165-L179) loses unfinished delegations. This is useful delegation functionality, but does not replace OSLit's durable task ownership, evidence sharing or independent review. It does not establish how private Omega-Pwn coordinates its investigators.

**Symbolic calculations.** [NAL](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/lib_nal.metta) and [PLN](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/lib_pln.metta) implement actual inference and uncertainty formulas. They can make specified relationships explicit and expose inconsistencies. The model supplies the premises and confidence values. Returned conclusions do not carry execution evidence, source-bound proof trees or checks that inputs arose from independent observations. The project's [failure discussion](https://github.com/singnet/Omega/blob/ba185cd359d9fe231b904110b988af39fafa5014/docs/reference-failure-modes.md#L9-L39) acknowledges the false-premise problem. A concrete compatibility question may warrant a task-local formal checker; this material does not justify a universal belief graph, mandatory numeric confidence or a second finding authority. Described confidence thresholds and novelty/inference scheduling were not found as mandatory mechanisms in the inspected core/plugin paths.

### Smallest useful changes to the plan

1. **Sharpen existing recovery checks.** Resume the same goal after losing context, recover an earlier negative and its surviving partial result, then test a connection enabled by new evidence. Include a plausible incompatible connection. The agent must choose and execute the next useful test without receiving the answer. This makes existing plan sections 1–2 concrete; it requires no graph or another notebook.
2. **Specify recovery from known temporary outages.** Retain unfinished work, use native retries where available and schedule another attempt when appropriate. Stop waiting when the operator stops the run. A known unexecuted request can be retried; an uncertain effect must first be reconciled. This is the clearest additional behavioral requirement worth discussing, implemented in existing runner/adapter owners rather than a new service. Do not retry permanent configuration failures indefinitely or stack duplicate retry loops.
3. **Keep active knowledge delivery and evaluated reuse.** Discover and load a relevant procedure during work, retain its selected version and preserve the accepted “not retained” continuation behavior when reference storage fails. Loading is separate from independent transfer/counterexample evaluation. These are already selected plan sections 3–4. Semantic ranking is an optional remedy for observed search failures.
4. **Measure research decisions and human steering.** First check interruption, safe resumption and stop behavior through the public workflow. Separately compare recovered valid connections, useful next experiments, unsupported joins and human interventions with an equally equipped native baseline. A sustained run measures operating continuity; duration or more model turns alone does not demonstrate better research.

No new universal experiment form, five-cycle minimum, query-before-every-turn rule, confidence gate, permanent symbolic planner or wholesale transcript capture follows from this review. Preserve important observations through existing records; investigate demonstrated loss before adding capture. The practical target is surviving ordinary interruptions and making earlier work available when it changes the next experiment.
