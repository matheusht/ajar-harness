## Result and selected implementation boundary

Use one owned native runtime process per engagement worker/generation. Bind its private host transport to the controller's immutable principal. Never accept `actor`, `role`, `worker_id` or generation supplied in a tool argument as authentication. Native session IDs remain observations mapped to that principal.

Both installed control protocols work without a provider. Neither native cancellation nor a shared worker token establishes durable revocation or isolation. Keep arbitrary lab execution outside the credential-bearing runtime boundary. A provider gateway must not be reachable by lab tools, including direct sockets, eval, built-in URL reads, subprocesses, SSH, and native child/revival paths.

For OMP, the smallest source-supported separation is a trusted model/session process with `--no-tools`, explicit host tools over `set_host_tools`, and an uncredentialed, isolated tool owner that instantiates the exact pinned OMP SDK `createTools` implementations. Forward their original names, descriptions, schemas, calls, results and cancellation; do not reimplement a shell/search/editor or add a second registry. Set `ToolSession.restrictToolNames=true`, use an explicit capability set without `task`, model-backed `find`/judges, advisor, memory or uncontrolled plugin/device discovery, and expose engagement status/claim/submit separately. This is a source-grounded implementation choice, not a run/containment pass. The selected allowed tools can include native read/edit/write/grep/glob/bash/eval/wait/debug where the isolated owner supports them. Tool factories requiring a model/credential are unavailable until their requests can use a separately admitted controller path.

The SDK import dependency must be pinned independently of the installed OMP executable: local global npm source is **18.14.2**, while the executable is **18.20.0**. Do not execute the old source as if it matches the current binary. SDK 18.20.0 installation/build and isolated-owner proof remain prerequisites.

Codex has native permission profiles, credential-path deny rules, reduced shell environment inheritance, and an active native network proxy. These are a plausible route to preserving its native tools with provider access outside tool access. `network.enabled=true` alone does not enforce domain rules. Native web search/apps/MCP/browser surfaces need their own restrictions. A profile is not yet qualified here; actual denial tests must cover alternate paths and credentials before execution is called enforced.

## Native reuse and gaps

| Concern | Codex 0.166.0 | OMP 18.20.0 |
| --- | --- | --- |
| Transport | App-server private stdio, JSON-RPC; `initialize`, then `initialized` | JSONL RPC (not JSON-RPC 2.0), `ready`; negotiate protocol 2 for bounded chunk reassembly |
| Fresh/session | `thread/start`, `thread/resume`, `thread/read`; fresh reviewer uses a new thread, never fork | `new_session`, `open_session`, `switch_session`, `get_state`; reviewer uses fresh session, never fork |
| Run/direction | `turn/start`, `turn/steer`, `turn/interrupt`; bind expected turn/thread | `prompt`, `steer`, `follow_up`, `abort`, `abort_and_restore_queue` |
| Completion | `turn/completed` status completed/interrupted/failed; item events carry actual tool observations | `prompt_result` reports yield; require `sessionSettled:true` or `session_settled`/`get_state.isSettled` before recycling environment |
| Tool bridge | Dynamic tools; `item/tool/call` includes threadId, turnId, callId, tool, arguments | `set_host_tools`; `host_tool_call` has id, toolCallId, toolName, arguments, **no worker/session identity**; process binding required |
| Usage | `thread/tokenUsage/updated`: last/total inputTokens, outputTokens, cachedInputTokens, cacheWriteInputTokens, reasoningOutputTokens, totalTokens | `get_session_stats`: tokens input/output/reasoning/cacheRead/cacheWrite/total; cost, premiumRequests. Inspect per-message usage for unique receipt accounting |
| Child control | Native multi-agent settings/threads exist; config/schema alone does not prove safe independent role ownership | `get_subagents`, `cancel_subagent`, `steer_subagent`, event subscription. Task uses same process or worker threads and a process-global registry; checkout isolation is not OS isolation |
| Revocation gap | Interrupt response is not resource absence; OS owner needs kill/readback and stale-generation deny | Explicit cancellation writes kill tombstone, but later `write agent://id`/Hub revival can reopen killed worker. OS owner and controller must forbid revival |
| Hard limits | Token events report observed usage; no strict whole-engagement token/spend cap established | CLI `--max-cost` is explicitly soft for in-flight requests; not strict spend control |

OMP private top-level host tools can be registered before any model prompt. Its pinned SDK exports `createTools`, `BUILTIN_TOOLS`, `BashTool`, `ReadTool`, `WriteTool`, `EditTool`, `GrepTool`, `GlobTool`, `EvalTool`, and `ToolSession` (`sdk.ts:1108–1124`). Minimum required ToolSession fields are cwd, hasUI, getSessionFile, getSessionSpawns, and settings. `createTools` accepts explicit names; `restrictToolNames=true` disables automatic expansion and xdev mounting (`tools/index.ts:663–790,878–980`). Additional tool-specific optional services need adapter configuration. Original schemas/results are available from each returned native Tool.

Ordinary cross-worker messaging is not automatically preserved between isolated top-level OMP processes; its agent registry/agent:// is process-local. Deliver consequential messages through typed submit and the recipient runtime's native steering. Do not advertise native same-process peer identity or child ownership as an enforced capability of this layout.

## Why process-origin alone is insufficient

The existing `tools/native_origin/main_linux.go:42–75,237–258` authenticates SO_PEERCRED and a live ancestry chain, including descendants. It does not distinguish a model connection from a shell child under the native process. Changing it to exact PID is also insufficient for OMP's in-process shell builtins and same-UID ambient filesystem/process access. Its existing nondumpable ingress is useful host protection (`:313–316`), but is not a general isolation policy for native tools.

OMP's pinned bash documentation explicitly says approval is not containment: commands keep ambient filesystem, network and subprocess access; eval can invoke the same shell and bypass bash-specific rules (`docs/bash-tool-runtime.md:48–50`). Native task `isolated:true` creates a checkout; it does not establish separate credentials or a network boundary. A shared per-worker provider capability merely attributes unauthorized direct-model spend to the worker; it does not forbid the bypass required by E04.

## Failure-first runtime workflow specification

1. Pin mismatch/unsupported schema → inspect refuses before session/provider launch; effective settings and tool inventory match required capabilities.
2. Missing credential or unavailable model → explicit unavailable result; no fallback model, no false completed research.
3. Fresh lead creates harmless file through native tool owner; retained session recalls its path after restart; fresh reviewer cannot see lead conversation but can inspect published artifact. Saved source/result digests and cleanup.
4. Spoof role/worker/generation in submit, direct shell/native pool/model call, stale message revival → no controller admission, provider dispatch or lab effect; only authenticated host transport matters.
5. Abort with background shell/eval/browser/child active → capability revoked first, owner readback proves resources gone; pending unknown effects remain held, no blind repeat.
6. OMP yield while background job remains → session not recycled until settled; Codex turn completion likewise does not substitute for owner readback.
7. Duplicate/delayed usage and restart → invocation settled once; unknown usage retains reservation. Strict unmeasured token/cost/request cap remains unsupported.
8. Tool output contains a fake secret sentinel → redaction before journal publication; runtime conversational storage stays protected outside export. No real secret can be used in the check.
9. Escape attempts through shell, eval, URL read, direct sockets, redirects, native spawn, helper process and provider endpoint → denied by actual sandbox/network authority, not a prompt or tool-name denylist.
10. Lease expiry/retirement → no further tool/provider admission; distinct replacement receives only published work and remaining allowance.

Live provider execution, session-content resume, active-tool stop, direct-model-bypass denial, Linux/container qualification, SSH and sustained multi-day behavior remain **unverified**. Docker/remote absence is an integration prerequisite, not grounds to claim these implemented capabilities unsupported forever or to silently reduce scope.
