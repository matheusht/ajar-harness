=== rate-limit constraint analysis ===
- GitHub core API: 5,000 req/hr per installation token (documented installation budget — the E12 amplifier's bound).
- Unauthenticated baseline: 60 req/hr (an attacker WITHOUT a token, e.g. probing or driving events that only hit unauthenticated endpoints).
- The fork-PR event stream requires NO attacker token: the PR events are created via the UI/API with the attacker's OWN low-rate account; the BUDGET consumption happens on the ANGULAR robot installation token (the labels/issue_labels/assistant jobs).
- Single-issue reopen loop: GitHub does not rate-limit issue reopen cycles per-se; the loop's bound is the job concurrency + the AI-key usage (issue_labels fires the Gemini call per event).
- Sustained impact: S3 (combined, 3,150 calls/hr) consumes ~63% of the hourly budget; S1 (6,000) and S5 (10,000) EXCEED it 1.2x-2x. Exceeding = the robot token throttles (429) for the window -> labels/status-check/merge-evaluation jobs fail intermittently -> PRs stall without labels/status; hourly recovery, no lockout (E2-R5/C5E NARROWED-SURVIVES; queue-wedge KILLED).
- DoS-vs-degradation verdict: per E2-R5/C5E the wedge is NARROWED-SURVIVES — budget exhaustion is real but bounded (hourly recovery, no lockout). The queue-wedge claim was KILLED (no merge calls).
