## 3. Failed attestation 2026-08-12 — cause, fix, and the general lesson

The first `complete-initialization.zsh` run signed correctly and then `init` rejected it with
`operator_signature_required`, details `sha256:b6cd8daf…7ee6`.

**The signature was never the problem.** The kernel printed the challenge it built and it was
byte-identical to `init-challenge.json`. The failure came from an earlier branch of
`_require_operator_console`:

```python
signer_match = re.search(rb"Operator allowed signers SHA256:\s*(sha256:[0-9a-f]{64})", scope_bytes)
if signer_match is None or not signature_name or not signers_name:
    raise RecordError("operator_signature_required", challenge_digest)
```

`scope.md` carried that line with **backticks** around the hash. The regex allows only whitespace
between the colon and `sha256:`. The backtick blocked the match, `signer_match` was `None`, and the
kernel raised the *same* error it raises when no signature was supplied at all. **The message points
at the signature; the fault was scope formatting.**

**The general lesson — two opposite conventions in one file, both fail closed:**

| Field family | Required form | Read by |
|---|---|---|
| `impact_demo_authorized`, `zone2_*` | **backticked** — `` `yes` `` | `require_scope_zone2_authorized` |
| `Operator` / `Reviewer allowed signers SHA256` | **bare, no backticks** | `_require_operator_console` |
| `- Signed: [x]`, `- Operator:`, `- Date:` | bare | `_scope_metadata` |

`_scope_metadata` accepts either, so a scope validates cleanly, passes conformance, and still cannot
attest. The same latent defect was found and fixed in `google-v8-2026-08`.

**Fix applied.** Backticks removed; scope re-frozen `023730ed…13a5` → `9feb17a3…bf3c`; challenge,
script `expected_scope`, and `OPERATOR-SIGNING.md` re-frozen together; a 9-check preflight that runs
the kernel's own regexes now precedes any freeze. The superseded signature is preserved unused at
`signers/init-challenge.json.sig.superseded-023730ed`.

## 4. Platform decision — macOS arm64 approved for this engagement

**Why it works here.** The surface is TypeScript, JavaScript, YAML and Starlark. The primary proving
method (`environment/BUILD-PLAN.md` §3.3) drives each composite action's own Node entry point against
a local mock API — pure Node, native on arm64. Docker reports `linux/aarch64`, so `act` runs **native
arm64 Linux containers with no emulation**.

**The one divergence, bounded.** GitHub's real runners are `ubuntu-latest` = linux/amd64. Irrelevant
for pure Node and TypeScript actions, which is nearly all of the surface. If a lane hits an action
shelling out to a prebuilt amd64 binary, run that one under
`act --container-architecture linux/amd64` (emulated, slower) and **record that you did**.

**Do not mistake the OS for faithfulness.** An `act` run on Linux proves no more about the real
trigger filter, `if:` conditions, `permissions:` block, or GitHub-side event validation than an `act`
run on macOS. Goal prompt Part 8 carries the evidence, not the kernel underneath.

**This covers this engagement only.** `google-v8-2026-08` requires Linux — its sandbox crash filter,
the primary oracle, is Linux-only. A distroless engagement would require Linux too.

## 6. B5 — environment preflight, the runner's first move

`preflight` is **Notebook tier, `allowed_roles: [broker]`** — an agent runs it, no operator needed.
It requires `signed_scope` (done) and `session_provenance`. It cannot run before the clone exists,
which is why this session left it open rather than pre-clearing it.

It matters because artifact registration is environment-bound: committing evidence with no active
environment ref raises `artifact_environment_not_active`. So preflight precedes any evidence or
Zone-2 artifact, not the reading.

Shape (fill the pinned commit; use `runtime-identity --role broker` for actor/session values):

```sh
./.venv/bin/python tools/run-engagement.py preflight \
  --engagement engagements/angular-dev-infra-2026-08 \
  --preflight-id preflight-angular-dev-infra-<pin> \
  --mode git --target upstream/dev-infra \
```
