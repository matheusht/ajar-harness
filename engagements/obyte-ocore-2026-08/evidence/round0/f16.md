## Triples

### T1 — Settlement tps fee can be astronomically large / Infinity; author tps_fees_balance poisoned permanently (candidate, needs lab proof)
- **mechanism:** `getFinalTpsFee` (storage.js:1228-1232) = `Math.round(base_tps_fee * (exp(tps / tps_interval) - 1))` with `exp(x)` = `new Decimal(x).exp().toNumber()` (storage.js:1133). `elapsed = (objMcUnitProps.timestamp - objLastBallUnitProps.timestamp) || elapsedTimeWhenZero` (storage.js:1174; `elapsedTimeWhenZero = 1`, storage.js:44). When the MC unit and the last-ball unit carry the same whole-second timestamp, `elapsed = 1`; `tps = count/1 = count` (units in the window between last_ball_mci and mci). For count ≥ ~30, fee ≈ 10×(exp(30)-1) ≈ 1.07e14 base units (~1e5 GBYTE); for count ≥ ~710, `exp()` overflows double → fee = **Infinity**.
- **source→sink→path:** attacker influences `count` (network rate in the window) or the equal-timestamp coincidence → `getFinalTpsFee` (storage.js:1228) → `updateTpsFees` (storage.js:1257-1281): `total_tps_fees_delta = (objUnitProps.tps_fee || 0) - tps_fee` (line 1261) → `Math.floor(delta * share / 100)` (1267) → `REPLACE INTO tps_fees_balances ... tps_fees_balance + tps_fees_delta` (1268-1270) → balance = −huge/−Infinity → future units from that author rejected: `if (tps_fees_balance + objUnit.tps_fee * share < min_tps_fee * share) return callback(...)` (validation.js:1087).
- **concrete input:** flood the DAG so a stabilization window contains ≥ ~30 units with the MC unit and last-ball sharing a timestamp (or set the MC unit's timestamp equal to the last ball — attacker-controlled unit timestamps up to `now+5`, validation.js:283-284), then observe honest authors' `tps_fees_balances` at that mci plunge negative in the local lab.
- **expected outcome:** authors whose units settle in the affected window get balances ≈ −huge; they can never transact again without paying astronomical fees (permanent freeze). The freeze is not attacker-selective (all authors at that mci) and recovery requires a coordinated fee-formula change.
- **negative control:** units settling in a window with normal elapsed (no equal timestamps, low count) keep delta ≈ 0; fee estimate at send time (composer.js:377-391, `getLocalTpsFee` storage.js:1329) roughly equals settlement when the rate is stable.
- **verdict:** mechanism real in source; severity depends on (a) whether rate spikes that large are reachable (self-limiting — the flooder also pays), (b) SQLite Infinity/NaN storage behavior (needs dynamic test), (c) the program's attack-investment/griefing feasibility rules. Route to economics review; keep as **candidate**, not suspected_success.

### T2 — `getRecentTps` counts future-timestamped units; `getCurrentTps` excludes them → attacker inflates the fee multiplier (griefing)
- **mechanism:** `getCurrentTps` skips future-dated units (`if (objUnitProps.timestamp > now) continue;` storage.js:1360) — the *fee-setting* estimate. `getRecentTps` does NOT skip them: `if (ts - objUnitProps.timestamp <= period) count += ...` (storage.js:1447) — a unit dated `now+5` has a negative diff ≤ 60 → counted — the *multiplier-setting* estimate. `getMinAcceptableTpsFeeMultiplier` (1452-1456): `recent_tps > 15 → multiplier 5`, else `1.5`.
- **source→sink→path:** attacker posts units with timestamps `now+1..now+5` (valid: validation.js:283-284 `max_seconds_into_the_future_to_accept = 5`) at ≥15/s sustained → `getRecentTps` > 15 (storage.js:1436-1450) → multiplier 5 (1453) → `min_acceptable_tps_fee = current_tps_fee * 5 * count_units` (validation.js:1075-1076) → **all** new units on the network must declare ≥5× the normal minimum fee.
- **concrete input:** in the local lab, submit spam units dated `now+5` at 16/s while the honest rate is ~5/s; observe `getMinAcceptableTpsFeeMultiplier()` return 5 and `min_acceptable_tps_fee` for a benign unit jump 3.3×.
- **expected outcome:** network-wide minimum fee ×5 for the spam duration; the attacker's spam is cheap because their future-dated units are excluded from `getCurrentTps` (the fee base stays low).
- **negative control:** the same spam with timestamps `<= now` raises `getCurrentTps` equally, so the multiplier rise is matched by a fee-base rise (no asymmetry); a node patched to exclude future timestamps from `getRecentTps` shows no multiplier jump.
- **verdict:** real asymmetry, but impact is fee inflation (griefing); likely below the $1,000 floor / 200%-expense feasibility bar → **real-but-capped** candidate; report the inconsistency (a one-line fix: skip `timestamp > now` in getRecentTps).

### T3 — Headers-commission winner grinding via SHA1 tie-break (weak)
- **mechanism:** `getWinnerInfo` (headers_commission.js:249-257): winner = child with lowest `sha1(child_unit + next_mc_unit)`. The child unit hash is attacker-controlled (grind content); a payer unit's headers_commission goes to the lowest-hash stable child within `mci - payer_mci <= 1`.
- **source→sink→path:** attacker creates N valid child units of a high-commission payer unit → `calcHeadersCommissions` (headers_commission.js:56-160, sqlite branch 91-160) → `getWinnerInfo` → commission to the attacker's winning child.
- **concrete input:** local fork; payer unit with a large `headers_commission`; grind children until one hashes lowest.
- **expected outcome:** attacker wins the commission they would not otherwise earn. Value bounded by the payer's voluntary headers_commission (small); grind cost is N valid unit fees.
- **negative control:** the same child set without grinding selects deterministically; commission value ≤ grind cost at normal fee levels.
- **verdict:** economically unattractive at current fee levels → **weak**, note for the economics review; the SHA1 design is deliberate (nobody can precompute), the grind is the residual.

### T4 — Paid-witnessing descendant-walk DoS (observation, out of scope by DoS rule)
- `graph.readDescendantUnitsByAuthorsBeforeMcIndex` (graph.js) walks the parenthood graph level-by-level in JS (one query per level) per MC unit during `buildPaidWitnesses` (paid_witnessing.js:213-288). A crafted deep chain of units within the `COUNT_MC_BALLS_FOR_PAID_WITNESSING` window multiplies queries per stabilized index → stabilization slowdown.
- **verdict:** a node-side fix (cap walk depth / use a recursive CTE) resolves it without network coordination → **out of scope** per the DoS coordination question (recon-signals.md). Recorded, not pursued.

## Held or refuted observations (with the decisive control)

- **H1 — data-feed read ranges are correct (not inverted).** `encodeMci` (string_utils.js:63-66) is deliberately reversed (`0xFFFFFFFF - mci`), so `gte=key+encodeMci(max_mci)`, `lte=key+encodeMci(min_mci)` in `readDataFeedByAddress` (data_feeds.js:330-338) is a valid descending range returning the newest value. Control: verified encoding direction + `getMciFromDataFeedKey` round-trip. **Held.**
- **H2 — feed value canonicalization is deliberate and consistent.** `toNumber` guards: mantissa-length > 15 → kept as string; `f === 0 ? 0 : f` replaces `-0`; `encodeDoubleInLexicograpicOrder` normalizes `-0 → 0` and flips sign bits (string_utils.js:141-158). No divergent canonical form found for hashed/compared feed values. **Held** (S5-negative here).
- **H3 — recipients shares cannot be 0 or non-integer.** `validateHeadersCommissionRecipients` (validation.js:1100-1124): positive-integer share, sorted addresses (isValidAddress BEFORE the `<=` comparison — the e56fa5c fix IS applied here), sum exactly 100. The `tps_fees_balance / share` divisions (validation.js:1089, storage.js:1413) cannot divide by zero. **Held.**
- **H4 — paid-witness commission math is cross-checked RAM-vs-DB.** JS `Math.round(payload_commission / count)` vs SQL `ROUND(1.0*payload_commission/count_paid_witnesses)` aggregated and compared with `_.isEqual` (paid_witnessing.js:222-250); mismatch → `throwError`. Half-up rounding agrees for positive values. **Held.**
- **H5 — witness list for paid witnessing is read from the MC unit, not the unit's own list** (`readMcUnitWitnesses` paid_witnessing.js:193-210; v4 → `storage.getOpList(mci)`, parsed from JSON at storage.js:2468). The side-chain witness-list-flip attack is explicitly defended (comment at 202-204). `op_list` is JSON-parsed (not a string) — no string/array bug. **Held.**
- **H6 — `paidWitnessEvents` / `max_spendable_mci` module globals are serial-only.** Sole callers: main_chain.js:1651/1655 inside `async.series` in the stabilization flow; `buildPaidWitnessesTillMainChainIndex` recurses index-by-index serially. No concurrent-writer path found. **Held.**
- **H7 — `getOversizeFee` Infinity overflow (storage.js:1145-1155).** `Math.ceil(size * (exp(size/threshold_size - 1) - 1))` → Infinity for size > ~710×threshold; the fee is charged to the SENDER (validation), so an oversized unit is simply rejected — self-DoS only. **Held as a finding candidate** (sender-side only).
- **H8 — balance display paths use `CAST(amount AS DOUBLE)`** (balances.js:15, 81) — precision loss > 2^53 possible, but display-only, not consensus. **Held/out-of-scope impact.**
- **H9 — initial_votes.js SQL is constant-only.** Values interpolated into INSERTs are compile-time constants (hardcoded OP addresses/voters); no user input reaches the SQL. **Held.**
