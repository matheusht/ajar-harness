## Triples

### T1 — mci/age/timestamp malformed-args gate bypassable via old-DAG attachment (REFUTED for theft)
- **mechanism:** `definition.js:483` — `if (!isArrayOfLength(args, 2) && (last_ball_mci >= pemCurvesFixMci || !hasBall && getMinRetrievableMci() >= pemCurvesFixMci)) return cb(...)`. A unit attached to the DAG **below** `pemCurvesFixMci` (12,155,000, `constants.js:101`) **with a ball** (`hasBall=true`) has `last_ball_mci < fix` and the disjunct's second arm is false (hasBall) → gate false → **malformed** `['mci', ['!=']]` (1-element args) passes structural validation. At spend time (`definition.js:1050-1061`): `args[1]` is `undefined`; `last_ball_mci !== undefined` → **always TRUE**; other relations (`>`,`<`,`>=`,`<=`,`=`) → always FALSE.
- **source→sink→path:** `validateDefinition` (phase-1 gate, definition.js:483) → stored definition → `validateAuthentifiers` phase-2 evaluation (definition.js:1050) → spend acceptance.
- **concrete input:** a unit attached to old parents (last ball < 12,155,000) carrying an inline definition `['or', [['sig', {pubkey: <attacker>}], ['mci', ['!=']]]]` for a new address.
- **expected outcome (if exploitable):** spend without key via the always-true branch.
- **decisive negative control (why REFUTED):**
  1. Spend-time re-validation: `validateAuthentifiers` FIRST calls `validateDefinition` (definition.js:1461-1465) with the **spend unit's** `last_ball_mci` (near tip, ≥ fix) → gate true → `cb("mci must have 2 args")` → spend **rejected**. A malformed-mci definition is permanently **unspendable** (self-fund-freeze only).
  2. An old-DAG-attached spend is **nonserial** (`checkSerialAddressUse` conflict logic, validation.js:1292-1310) → no value transfer regardless.
  3. The unused-authentifiers check (`definition.js:1510`: `arrUsedPaths.length !== Object.keys(assocAuthentifiers).length` → reject) blocks an author whose sig path isn't consumed by the definition.
- **impact:** attacker can only freeze their OWN funds by creating a malformed definition; below the program's USD 1,000 minimum and 200%-expense rule → **not reportable**. Recorded as a held/refuted with the decisive control (the spend-time re-validation gate).
- **residual:** `['mci', ['!=']]` is the only always-true malformed form; `['mci', ['>=']]`-style are always-false dead branches. Creation requires a deep-DAG attachment which is itself nonserial.

### T2 — `sum` op JS-Number float arithmetic (weak registry)
- **mechanism:** `definition.js:1228-1245` — `sum += arrFoundObjects[i].amount` (double) then `sum === args.equals`. Precision loss only beyond 2^53.
- **path:** definition `['sum', {filter, equals}]` → `augmentMessagesAndEvaluateFilter` → float sum.
- **input:** amounts summing past 9.007e15 base units.
- **why weak:** Obyte base supply ≈ 1e15 base units; issued-asset caps bounded; `!isFinite(sum)` → throw → reject (fail-closed). No realistic precision-loss window. **Registry only.**

### T3 — `formula` op: `/input/.test(formula)` augmentation heuristic (held)
- **mechanism:** `definition.js:1286-1292` — `augmentMessagesOrIgnore` augments message inputs only if the formula string contains `/input/` (case-sensitive).
- **why held:** oscript keywords are lowercase `input`/`output` (`formula/grammars/oscript.ne:71,433`); any input access path (`input[...]`, `messages[i].payload.inputs`) contains "input". Under-augmentation impossible in the current grammar; augmentation failure is conservative (`err → cb2(false)`).

### T4 — `handleDuplicateAddressDefinition` race (team-flagged, cross-family)
- **mechanism:** `validation.js:1460-1474` — the bNonserial bypass is commented out; active code rejects duplicate definitions. The team's own comment: *"todo: investigate if this can split the nodes — attacker changes his definition then quickly sends a new ball with the old definition — the new definition will not be active yet."*
- **why weak:** active code rejects duplicates; the pending-definition race is main-chain/stability territory (**signal for f2**), not a definition.js bypass.
