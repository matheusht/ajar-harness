## Triples (candidate hypotheses)

### T1 — [SUSPECTED_SIGNAL, experimentally confirmed mechanism] is_valid_signed_package complexity/count budget bypass via old-DAG attachment (S1 family)

- **Mechanism:** evaluation-side resource gates for `is_valid_signed_package` are keyed on the bare
  unit position `mci >= constants.pemCurvesFixMci` — WITHOUT the `|| !hasBall && getMinRetrievableMci() >= X`
  disjunct the team has been adding to validation-side gates (recon-signals S1; fixed-in `277fad7`,
  `048fbdb`, `c368211`).
  - `formula/evaluation.js` (`is_valid_signed_package` case, ~line 1655): `const max_complexity = mci >= constants.pemCurvesFixMci ? 10 : 0;`
  - `formula/evaluation.js` (~line 1652): `if (objValidationState.count_signed_packages >= constants.MAX_SIGNED_PACKAGES_PER_AA_EVAL && mci >= constants.pemCurvesFixMci) return setFatalError(...)` — the 3-package cap is likewise skipped below the gate.
- **Source→sink→path:**
  1. Attacker authors an AA whose `init` formula calls `is_valid_signed_package(<pkg>, <addr>)` up to ~100× (each call = +1 complexity; no count_ops charge; 100 ≤ MAX_COMPLEXITY; dictionary-literal args cost no complexity). Formula validation passes (`formula/validation.js` — only gate is non-AA usage; no count/complexity caps on the call).
     - `validation.js:1765` → `aa_validation.js validateAADefinition` (line 550: complexity/ops check ≤ 100/2000) — passes.
  2. Attacker attaches the AA-definition and trigger units to an OLD part of the DAG so `objValidationState.last_ball_mci < pemCurvesFixMci` (same premise the team's own `277fad7`/`048fbdb`/`682e136` fixes defend against — "enforce rules for all new units even if attached to an old part of the DAG").
  3. Every full node: trigger recorded → `writer.js:722/752` `aa_composer.handleAATriggers()` → `handlePrimaryAATrigger` → formula evaluation → `is_valid_signed_package` → `signed_message.validateSignedMessage(conn, pkg, addr, max_complexity, cb)` with **max_complexity = 0**.
  4. `definition.js:110/632`: `if (objValidationState.max_complexity && ...)` — **0 is falsy → the custom complexity budget is entirely skipped**; the inner definition validation runs up to the GLOBAL MAX_COMPLEXITY=100 (10× the intended 10) per signed package.
  5. Per-call cost: DB query `SELECT main_chain_index FROM units WHERE unit=?` (`formula/evaluation.js` is_valid_signed_package case) + per-author `readDefinitionByAddress` + `Definition.validateAuthentifiers` (full definition walk up to 100 complexity) + signature verification. Times ~100 calls (cap skipped), times up to `MAX_AUTHORS_PER_UNIT` authors.
- **Concrete input:** AA definition formula: `$ok = is_valid_signed_package({signed_message: "x", authors: [{address: "<valid>", authentifiers: {r: "<sig>"}}]}, "<valid>");` repeated ~100× with distinct literals; unit attached below pemCurvesFixMci.
- **Expected outcome:** ~330× amplification (100 calls vs 3, × 10 complexity budget) of CPU + DB work per AA trigger on every full node that stabilizes the trigger — a valid unit, so propagation is automatic and no node can unilaterally reject it. Recovery requires a coordinated node upgrade (rejecting old-DAG units) → **in scope per the DoS coordination rule** (temporary freezing of network transactions / availability degradation).
- **Negative control:** identical formula evaluated with `last_ball_mci >= pemCurvesFixMci` → max_complexity = **10** (observed) and 3-package cap applies.
- **Local experiment (decisive, throwaway script, since deleted):** with `pemCurvesFixMci = 1000000`, formula `$x = is_valid_signed_package({...}, "<valid addr>");`:
  - mci=500000 → `validateSignedMessage` called with `max_complexity=0`
  - mci=1500000 → `max_complexity=10`
  Both evaluated to `res=true` (mocked downstream), proving the position-gated budget divergence.

### T2 — [WEAK] evaluation-side size caps gated on bare mci (incomplete disjunct migration)

- **Mechanism:** `formula/evaluation.js` caps use `mci >= constants.pemCurvesFixMci` WITHOUT the disjunct: min/max/hypot `>30` args; array literal `>100`; dictionary literal `>100`; `filterBySearchCriteria` array-length and 5-criteria caps; `is_valid_merkle_proof` sibling validation; `is_valid_signed_package` (T1). The corresponding `formula/validation.js` gates HAVE the disjunct (`|| getMinRetrievableMci() >= pemCurvesFixMci`).
- **Path:** validation runs first and (on a network past the fix MCI) refuses the oversized forms via the disjunct → the eval-side bare gates are unreachable for new units → **not exploitable today**. Records an incomplete migration (the team added the disjunct to validation.js but not evaluation.js); any future validation relaxation re-opens it. Watch item for the S1 audit.
- **Negative control:** oversized min/max/array/dict refused at validation for any unit when `getMinRetrievableMci() >= pemCurvesFixMci`.

### T3 — [WEAK] unbounded console.log noise during AA processing (log-DoS / log-file growth)

- **Mechanism:** `console.log('log', entries)` (evaluation.js `log` op), `console.log('bounce called: ', ...)` (`bounce`), `console.log('require not met:', ...)` (`require`), `console.log('early return with: ', res)` (`return`), `console.log(err)` in `setFatalError`, `console.log('func', func)` (`formula/validation.js` func_call), `console.log('handleAATriggers', ...)` (`aa_composer.js`). An attacker-controlled AA can force many bounces/log calls per unit; each logs attacker-supplied data (incl. trigger content) to the node console → log growth / noise on every full node.
- **Path:** AA formula with `log(...)`/`bounce` ops → node console. Cost to attacker: bounce requires `MIN_BYTES_BOUNCE_FEE` (10000 base) per bounce in the trigger; `log` is cheaper.
- **Expected outcome:** log-flood / disk-fill degradation. **Fix (remove logs) does NOT require network coordination → out of scope per program rules.** Recorded as a quality issue, not a reportable finding.
- **Negative control:** benign AA (no log/bounce) produces no console output.

### T4 — [WEAK] search_param_list ops-accounting line not migrated to the disjunct

- `formula/validation.js` (`search_param_list`): `if (mci >= constants.pemCurvesFixMci) count_ops += arrPairs.length;` — bare mci (the `>5` cap right above HAS the disjunct). For old-DAG units the ops cost of search params is not charged; max 5 pairs → ≤5 ops. Negligible impact; S1-audit watch item.

## Held or refuted observations (with the decisive control)

- **R1 [REFUTED by experiment] — func-call-after-return → uncaught throw → node crash (Q-A lane 3).**
  `callFunction` (`evaluation.js:3059`) throws `"function called after a return"` when `early_return` is set, and `network.js:4367` crashes the process on uncaught exceptions. Hypothesis: `$f = () => { return 1; }; return; $f();` passes validation and crashes every node. **Experiment:** the top-of-`evaluate` guard (`evaluation.js:169`: `if (early_return !== undefined) return cb(true);`) short-circuits the post-return func call before `callFunction` runs — formula evaluated cleanly (`err:null res:true`). The throw is unreachable through the evaluate guard. Decisive negative control performed locally.
- **R2 [HELD] — parser cache keyed by formula string only, shared across AAs.** `common.js` cache stores the parsed AST by formula text; no per-address key. No AST mutation found in evaluation (all mutations target runtime state, `wrappedObject` copies, or `cloneDeep`'d objects) → no cross-AA cache poisoning found. `fixFormula` patches only 9 testnet addresses. Watch item (future ops must not mutate AST nodes).
- **R3 [HELD] — `-0`/canonicalization (S5).** `toDoubleRange` (`common.js`) expunges `-0` and underflow→`Decimal(0)` on every arithmetic result, comparison, and stored value; `json_parse` applies `string_utils.replaceNegativeZero`; object state vars round-trip through `getJsonSourceString` (JSON: `-0`→`0`); `round` uses `ROUND_HALF_EVEN`; `Decimal.set({precision:15, rounding:HALF_EVEN})` is process-global and pinned via `decimal.js 10.6.0` in package.json; `join`/`json_stringify` sort keys; `comparison` of objects uses `util.isDeepStrictEqual` (key-order independent). No divergent-canonicalization path found in formula evaluation. **Notable:** `json_stringify` and `sha256`/`chash160` of objects use `string_utils.getJsonSourceString` (sorted keys) — the canonical serializer — consistently.
- **R4 [HELD] — `bLimitedPrecision = mci < aa2UpgradeMci` position-gated semantics.** String→number conversion precision and object-var handling differ by unit position (deliberate legacy semantics). Deterministic per position — nodes agree on a unit's `last_ball_mci`, so no cross-node divergence. Not a finding.
- **R5 [HELD] — eval-side `isTooBigObj` bare-mci branch.** `mci >= pemCurvesFixMci ? isTooBigObj : isTooDeeplyNestedOrHasTooManyNodes` — two size regimes by position; deterministic; validation-side caps gate entry. Held.
- **R6 [HELD] — state-var write atomicity.** `state_var_assignment` validates types/sizes before writing (`MAX_STATE_VAR_VALUE_LENGTH` 1024, `MAX_STATE_VAR_NAME_LENGTH` 128, `isWellFormed`, object JSON length check); `+=`/`-=` require Decimal current values (error → bounce, no partial write observed). Object state var writes `cloneDeep` before storing (mutation-safe). Held.
- **R7 [HELD] — has_only RegExp construction.** `new RegExp("^[" + sub + "]*$")` with `]`-escaping; a leading `^` in `sub` negates the class (semantics inversion) — formula-author footgun, deterministic across nodes, not consensus-relevant. Log noise noted (T3). Held.
- **R8 [HELD] — trigger.data / params / previous_aa_responses sizes.** `cloneDeep`'d into wrappedObjects without an explicit cap, but input bounded by unit size (MAX_UNIT_LENGTH 5e6); mutations gated by `isTooBigObj`; reads O(n) with n bounded by unit size. Held.

## Suspected_success candidates

- **T1 only** — `is_valid_signed_package` complexity/count budget bypass via old-DAG attachment.
  Evidence-backed: static mechanism with exact file:line, plus a decisive local experiment showing
  `max_complexity=0` (limit skipped) for old-position units vs `10` for new units. Needs the
  orchestrator's multi-node lab to (a) confirm old-DAG attachment passes full unit validation,
  (b) confirm the deployed `pemCurvesFixMci > 0`, and (c) measure the CPU/DB amplification per
  trigger to grade severity (availability degradation → Medium-ish per the reward ladder; in-scope
  only if resolution requires network coordination).

## Gaps not covered and why

- **Full-node DB integration:** my experiments mocked `storage`/`signed_message` downstream. The
  real `validateSignedMessage` (DB reads, light-client fallback) and real signature verification
  were not executed — the orchestrator's lab should run the full AA-trigger path end-to-end for T1.
- **Getters end-to-end:** `executeGetter` (network.js:3864, remotely callable) evaluates getter
  formulas with attacker args; getters are complexity-0 by construction, but the remote-call
  amplification ("which can also amplify other expensive ops" — code comment at evaluation.js:31)
  was not exhaustively quantified. Recommend a lab probe: expensive-but-valid getter chains.
- **data_feed / attestation DB query volume:** per-op DB queries are bounded by MAX_COMPLEXITY, but
  an attacker choosing a distinct (oracles, feed_name) per call forces uncached DB reads — minor,
  not quantified.
- **formula/error/errorFormatter + astTrace growth:** long formula evaluations push every visited
  node into `astTrace` (unbounded-ish memory within MAX_OPS=2000) — bounded, not quantified.
- **AA response-chain depth across multiple AAs** (A→B→C responses) is handled by the composer's
  response loop (MAX_RESPONSES_PER_PRIMARY_TRIGGER=10); the formula side per-trigger was covered,
  cross-AA chain amplification was not exhaustively walked.
