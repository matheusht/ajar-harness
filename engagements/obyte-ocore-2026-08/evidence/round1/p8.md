## Part (c) — old-DAG attachment passes full unit validation (the S1 prerequisite): determined statically

1. `validateParents` (`validation.js:639-833`) requires parents to exist/be valid/ordered — **no recency requirement**; old parents are legal.
2. AA-trigger outer gate (`validation.js:986-992`) skips trigger validation only for `bAA || !last_ball_mci`; a non-AA unit with `0 < last_ball_mci < v4UpgradeMci` falls through to the (disjunct-gated) inner checks — not blocked.
3. The AA-definition old-DAG guard (`validation.js:1752-1754`) is **transient** and requires `!hasBall` — a definition unit with a ball attached below the fix passes (matches f1-T7).
4. Authoritative evidence: commits `277fad7`, `048fbdb`, `682e136` — "enforce some new rules for all new units, **even if attached to an old part of the DAG**" — are the team closing exactly this class; new-units-on-old-DAG is a real, defended-against attack surface.

A trigger validated with `last_ball_mci < pemCurvesFixMci` (which the validation gates allow) evaluates the AA with the evaluation-side gates skipped.
6. **Remaining link (not demonstrated in this PoC):** whether an old-attached trigger unit becomes **stable** (gets a ball, runs the AA) on the real network — MC/stability territory (f2's PoCs). The eval-side divergence itself is proven; the trigger-stabilization link is the reachability boundary.
