# E1-5 — parent_composer.js:461 "all potential parents underpay the tps fee" crash lane

**Hunter:** E1-5 · **Pinned:** ocore `a7eb776afc68ed4bed05ba554f7f1e95f5d49b44` · **2026-08-11**
**Verdict: CONFIRMED mechanism + CONFIRMED crash propagation; reachability = pool-flood (partial,
source-traced); impact = wallet/node process death or permanent hang (availability class).**

## 1. What triggers the throw (confirmed by real-path reproduction)

`pickParentUnitsAndLastBall` (parent_composer.js:353) selects the node's free-unit pool
(`WHERE sequence='good' AND is_free=1 AND timestamp<=now ORDER BY last_ball_mci DESC LIMIT 16`),
then `filterParentsByTpsFeeAndReplace` (parent_composer.js:426-462) excludes every non-AA candidate
whose `getPaidTpsFee(unit) < current_tps_fee * min_parentable_tps_fee_multiplier` (default 3,
parent_composer.js:429-432) **unless it is authored by the composer's own from-addresses**
(exception at 445-449). Excluded units are replaced from their parents (`replaceParents`,
parent_composer.js:500-556); if replacements are added the filter recurses (458). When no
replacement is available and `filtered_prows` is empty → **`throw Error("all potential parents
underpay the tps fee")` at parent_composer.js:461**. (Sibling: 478, `"all potential parents have
the top OP list"`.)

**Reproduction (evidence/lab/e15/e15-parent-crash.js, real path):** synthetic genesis → 16
attacker-authored free units seeded at `tps_fee=1` (is_free=1, off-MC, schema-exact rows + kvstore
joints + parenthoods + unit_authors, in-memory cache populated via `initUnstableUnits`) → the
victim's FIRST composition (a fresh address with no own free units). Raw log
(`evidence/lab/e15/e15-throw-repro.log`):
- 16 × `skipping potential parent ... paid tps fee per unit 1 < min parentable tps fee 21`
- `replacement_parents [<genesis>]` → genesis added → then
  `skipping potential parent <genesis> ... paid tps fee per unit 1 < min parentable tps fee 21`
  (genesis paid fee = 0 per `getPaidTpsFee` special case, storage.js:1402)
- `replacement_parents []` → no replacements
- **`E1-5-UNHANDLED-REJECTION: Error: all potential parents underpay the tps fee`** → process death
  (Node 15+ unhandled-rejection default; network.js:4367's uncaughtException handler would re-throw
  if reached).

## 2. Propagation shape (confirmed)

The throw occurs inside the `conn.query` **async callback** of `pickParentUnitsAndLastBall`
(parent_composer.js:371-407, `async function (prows)`). The callback's rejected promise is never
awaited by the sqlite pool wrapper (sqlite_pool.js:108-131 calls the callback and ignores its
return). Two caller shapes exist:
- **Callback API** (composer.js:361, 862): the `onDone(err)` path is bypassed — the callback never
  fires → the composer **hangs forever** (no timeout) if the rejection is swallowed, or the process
  **crashes** via the unhandled rejection (Node ≥15 default).
- **Promise API** (composer.js:621 `await parentComposer.pickParentUnitsAndLastBall(...)`): same
  escape — the wrapper promise never settles → hang/crash.

**Observed in the repro: unhandled rejection.** This is the same uncaught-throw-on-attacker-input
family as HN-2 (validation.js sites) — a composer-layer sibling. Additionally it is a **fail-open
design bug**: the error should have been delivered via `onDone(err)` (like the sibling branches
"no usable free units", "unable to find parents") but the throw bypasses the error path.

## 3. Attacker-reachability (partial — pool-flood, source-traced; lab seeded the pool)

The attacker does not control the victim's composer, but CAN control the victim node's **free-unit
pool**: (a) any peer's valid units are validated and stored as free units by the victim node; (b)
the pool is capped at `LIMIT 16` ordered by `last_ball_mci DESC` — the attacker floods 16+
tip-anchored units (highest last_ball_mci) so the victim's OWN free units (older last_ball_mci) fall
off the cap and the "self-authored exception" never sees them; (c) the attacker's units declare the
minimum fee at their (low-rate) composition time, so `paid < 3× current` when the rate later rises
(natural or attacker-driven) — the filter then excludes the entire pool.

**Honest caveats:** (1) the lab seeded the pool directly (a fresh victim with no own free units);
the flood-to-fill-top-16 shape is source-traced (ORDER BY last_ball_mci DESC LIMIT 16), not
multi-node demonstrated — the lab cannot stand up a real network (documented residual); (2) a
victim with a recent self-authored unit still in the top-16 is protected (exception 445-449); the
attack targets fresh wallets, wallets whose own units stabilized/archived, and **nodes composing AA
responses** (aa_composer.js:936/1873 → sendUnit → composeJoint → the same parent selection).

## 4. Impact assessment (marginal contribution)

- World without the bug: parent selection returns a clean `onDone(err)` (sibling branches) → the
  composition fails gracefully; the wallet shows an error; the user retries when the pool changes.
- Delta this bug adds: the wallet/node **process dies** (unhandled rejection → crash) or **hangs
  forever** (callback never invoked). Repeated crash-loop if the victim keeps retrying.
- Class: availability/robustness. DoS-coordination: a node-side fix (wrap the filter in try/catch →
  `onDone(err)`) resolves without network coordination → **out of scope** per the program rule
  (like HN-2). No fund-loss path.
- **Verdict: `capped`** — real crash mechanism, attacker-influenceable pool, but (a) pool-flood
  reachability not multi-node demonstrated, (b) node-side-fixable → out-of-scope availability
  class, (c) no fund impact. Recommended: **hardening note (HN-12)** + optionally a Low
  robustness finding at the operator's discretion.

## 5. Fix direction

- `filterParentsByTpsFeeAndReplace`: replace the bare `throw` with `onDone`-style error delivery
  (the callback already carries errors); the throw at 461 and 478 should return the error.
- Add a process-level guard: an unhandled-rejection handler that routes to the eventBus
  `nonfatal_error` instead of crashing (defense-in-depth for the whole async-completion family,
  HN-2).
