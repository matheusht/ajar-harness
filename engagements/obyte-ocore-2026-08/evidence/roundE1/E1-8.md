## Why this strengthens the finding (the descendant variant)

The round-2 establish side demonstrated the fork variant (attacker's unit in a competing branch).
This experiment shows the stronger construction: the composer attaches the ghost **directly on the
accepted payment unit** (A's parent = C, the current tip at publication). On the real network, the
attacker simply times their ghost after the merchant's payment is included. The merchant's node:

1. accepted C (`'good'`, on-MC) → the merchant's acceptance criterion is satisfied;
2. then accepted A (`'good'`, on-MC, **descending from C**, same spend proof P) with no rejection,
   no error, no warning;
3. retains both units `'good'` — `markMcIndexStable`/`handleNonserialUnits` resolve only
   non-`'good'` units, and no author-keyed conflict fires (different authors), and the input-level
   check cannot run network-wide (the private payload is not in the unit; `bPrivate` is set only in
   the payload flow, validation.js:2695).

## Exposure window (quantified)

- **T0:** C is saved `'good'` on-MC — the merchant's acceptance signal turns true.
- **T1:** the ghost A arrives and is accepted `'good'` — the merchant's signal remains true, and the
  ledger now holds two `'good'` units with the identical spend proof.
- **T1 → ∞:** no resolution mechanism exists for this pair (same-author conflict detection is
  author-keyed; spend-proof uniqueness is address-keyed; the payload-side binding rejects the
  ghost's payload but is per-node, not network consensus). The exposure window is **unbounded**.
- A merchant acceptance flow keyed on `'good'` + inclusion (a common, sound rule for public
  payments) treats the contested payment as valid — the payment can be silently contested forever.

## Marginal contribution (anti-reward-hack)

- World without the bug (the check keyed on the output owner, as the payload-side recomputation
  already does at divisible_asset.js:120-136): the ghost A would be rejected at unit level on every
  node the moment the merchant's row `(P, merchant)` exists — the merchant is safe after C's
  inclusion.
- World with the bug: A coexists as `'good'`; the merchant's acceptance assumption is wrong. **The
  delta = the disappearance of the designed unit-level rejection** — the check was built precisely
  to prevent this (the 05f291d8 fix and the check's existence confirm it is a first-class
  invariant). No new theft mechanism is claimed (the ghost's payload is rejected by the owner
  binding) — the exposure is the loss of the detection/rejection guarantee, which is what a
  merchant's acceptance logic depends on.

  provenance, so the mechanism is faithful; a full private-asset end-to-end (with real blinding)
  was already established by the round-2 experiments.
