## 2. The flood trigger cost (measured + real-network scaling)

E2-8's end-to-end lab (raw log `evidence/lab/e28/e28b-run.raw.log`):
- 16 flood units composed through the real path, each declaring the minimum fee at its rising
  composition rate: declared fees 2,2,2,2,10,10,10,10,10,10,11,11,12,12,14,14,20,20… — total
  declared ≈ 200-300 base units.
- The flood raised the current rate 0 → 33/s (lab fast-elapsed mode); `min_parentable = 7×3 = 21`
  (current_tps_fee × `conf.min_parentable_tps_fee_multiplier || 3`, parent_composer.js:427-429).
- Every pool parent (fee 1) excluded; the genesis replacement (fee 0) excluded; no replacements →
  `throw "all potential parents underpay the tps fee"` → unhandled rejection.

Real-network scaling: the trigger condition is `current_tps_fee > 3 × (pool paid-fee rate)`. The
attacker must push the real-time rate above 3× the steady-state rate R for the composition window
(seconds). At R=1/s with base_tps_fee=10: pool units paid ≈ 17 base; the flood sustains ~3/s for
seconds; total cost ≈ a few hundred to a few thousand base units — **fractions of a GBYTE,
trivially affordable, remote, unauthenticated** (any peer's valid, fee-paying units enter any
node's free-unit pool).

## 3. Crash mechanics — uniform across caller styles

`pickParentUnitsAndLastBall`'s query callback is `async function (prows)` (parent_composer.js:374);
`await filterParentsByTpsFeeAndReplace(...)` (parent_composer.js:401) — when the filter throws, the
async callback returns a REJECTED promise. The `conn.query` wrapper (sqlite_pool.js) invokes the
callback without awaiting it → **unhandledRejection**. ocore registers NO `unhandledRejection`
handler (grep: zero matches outside node_modules) → **Node 15+ default: process crash**. The
`onDone`/`cb(err)` guards in the callers (e.g., light.js:611 `if (err) return callbacks.ifError`,
composer.js:862's err handler) NEVER fire — the error is a rejected promise, not a callback error.
Both the promise-style (composer.js:621) and callback-style (light.js:606, composer.js:361/862)
callers crash identically. E2-8's raw log observed exactly this: `E2-8-UNHANDLED-REJECTION: Error:
all potential parents underpay the tps fee` → process crash.

## 4. Crash-looping (persistence)

- The victim wallet retries composition → the pool is still dominated by the attacker's fee-1
  flood units (they persist as valid free units) → crash again. Crash-loop while the flood units
  dominate the top-16 pool (`ORDER BY last_ball_mci DESC LIMIT 16`, parent_composer.js:367-372).
- The current rate decays when the flood stops (real-time) — once `current_fee × 3` falls below
  the pool's paid fees, composition succeeds again. Sustained flooding extends the window.
- The victim exception (parent_composer.js:445-449 — parents authored by the composer's own
  from-addresses are kept) protects clients with recent own free units. Victims: fresh wallets,
  wallets whose own units stabilized/archived, exchange hot wallets with no pending own units,
  and light vendors.

## 5. Marginal-contribution critique (severity sizing for HN-14)

- **World without the bug:** the filter returns `onDone(err)` (the sibling branches do — e.g.,
  `onDone("no usable free units")` at parent_composer.js:383-385) → the composition fails
  gracefully → user-visible error → retry when the pool changes.
- **Delta this bug adds:** process death (unhandled rejection) + crash-loop on retry; for light
  vendors: mass disruption of all served clients (shared chokepoint, escalation-move-3 widening).
- **Caps (proven):**
  1. Node-side fix (replace the throw with `onDone(err)`-style delivery) resolves it WITHOUT
     network coordination → **out of scope** per the program's DoS-coordination rule.
  2. No fund-loss or fund-freeze path (the composition is client-side; nothing moves value).
  3. Below the USD 1,000 minimum impact (client availability only).
  4. The network-wide AA-response crash class is REFUTED (AA responses bypass the filter).
- **Verdict:** capped at **Low client-availability**; HN-14 stands as a hardening note. Not
  reportable under Primacy of Rules; the operator may forward the fix direction to the vendor
  (throw → error delivery, and a process-level unhandledRejection handler that routes to
  `eventBus nonfatal_error`).

## 6. Honest caveats

- The lab's absolute rate numbers (33/s) come from fast-elapsed lab mode; real-network rates
  differ, but the trigger ratio (3×) and the exponential fee curve make the attack cheap at any
  realistic steady-state rate. The flood's rate-elevation on a live network is not
  multi-node-demonstrated (the lab seeds the pool directly) — same residual as E1-5/E2-8.
- The light-vendor fan-out is source-traced (light.js:606 handler) but not empirically crashed in
  this lane (E2-8 crashed a composer path; the vendor path has the identical call structure).
