**Status: CAPPED — no escalation.** Both half-up rounding sites can create value in mechanism, but
neither is exploitable. This report corrects E2-11's mechanism analysis and confirms its conclusion
with measured numbers.

## Item 1 — paid-witnessing half-up: creation real, recipients not attacker-selectable

`Math.round(comm/count)` per witness can exceed the burned commission (comm=5,count=2 → paid 6,
+1 created; measured pattern), bounded < count per unit (≤11 with 12 witnesses). **The recipients
are the MC-unit-designated witnesses (the governance-selected OP list); an attacker cannot become a
witness without the governance vote (out of scope).** An OP's own influence over the count
(ensuring few OPs authored) is bounded and requires governance trust — the "creation" benefits the
OP list, not an attacker. **Not exploitable.**

## Item 2 — headers-commission half-up: mint real in mechanism, dead by economics

### The mechanism (verified in source + arithmetic)

1. The winner child (lowest sha1(child_unit+next_mc_unit), headers_commission.js:249-257) can be
   attacker-authored: **sole child → wins without grind** (getWinnerInfo returns arrChildren[0]
   directly when length===1); with competitors → sha1 grind (unit-hash content control — E1-2
   confirmed the grind space).
2. The winner's recipients = its `earned_headers_commission_recipients` — **external addresses
   allowed** (validation.js:1100-1126 checks only sortedness, validity, positive-integer shares
   summing to 100 — no author constraint). The attacker can name up to 100 own addresses (share 1).
3. The split `Math.round(full_amount*share/100.0)` is half-up (JS Math.round(0.5)=1, measured).
4. **The mint (measured):** with N=100 recipients share 1 and payer hc A ≡ 50 (mod 100):
   each recipient gets round(A/100) = k+1 → total = A+50 → **+50 created per payout**. Max mint
   bounded at ~50 (shares are positive integers summing to 100 → N ≤ 100; E2-11's N=200/1000 rows
   were impossible). Measured: A=50→+50, A=150→+50, A=250→+50, A=4850→+50; N=50 never yields +50.
5. **The hc IS recyclable** (correction to E2-11): the payer's hc is credited to the winner's
   recipients (headers_commission_outputs — spendable via the "headers_commission" input type,
   validation.js:250). A winner-chain (P ← C1 ← C2 ← ...) recycles each hop's hc back to the
   attacker's addresses, so the header cost (~5,000 units for N=100 recipients) is NOT lost —
   E2-11's "commission ≈ 50N" cost assumption (which charged the header as lost) is wrong.
6. **The header-size grind is feasible:** hc is enforced as the true header size
   (validation.js:256), but the header size is controllable in 1-byte steps via the version-string
   length (measured: "4.0"=378, "4.00"=379, "4.0.0"=380, "4.0.0.0"=382 — all parseFloat ≥ 4) →
   hitting A ≡ 50 (mod 100) is offline-grindable.

### The killer (measured): the mandatory minimal payload commission

- `messages` must be non-empty (validation.js:57 `isNonemptyArray` → empty fails the hash check).
- The minimal valid message (1 text message) → `getTotalPayloadSize` = **79** (measured via the
  real object_length.js; the payload commission is reconciled against this, validation.js:260).
- Per-hop P&L with the recycle: **mint +50 − payload_commission(≥79) − tps_fee(≥0 at the
  quietest) = net ≥ −29 units per hop**, at every recipient count and every payer size:

| rate (tps) | per-hop cost (pc 79 + tps) | mint | net |
|---|---|---|---|
| 0.017 (1 unit/60s) | 79 + 0 | +50 | **−29** |
| 1 | 79 + 17 | +50 | **−46** |
| 5 | 79 + 1,474 | +50 | **−1,503** |
| 17 | 79 + 2.4e8 | +50 | **−2.4e8** |

The mint can never cover the mandatory message cost. **Economically dead by ≥29 units per hop at
the absolute quietest, and by orders of magnitude at any real rate.** E2-11's conclusion stands;
its mechanism was wrong (the header is recycled, not lost) and its N>100 rows were impossible —
the real killer is the minimal-message payload commission, which survives every construction.

## Item 3 — accumulation over time: NONE

Every hop has a strictly negative P&L (≥ −29 units), so the dust cannot compound. No value
accumulates; the attacker loses at least the minimal payload commission minus the bounded mint
per unit authored. The oversize fee (storage.js:1137-1155) makes large-N constructions
astronomically negative on top.

## Corrections to the record (E2-11 / E1-10)

1. E2-11's "payload commission ≈ S (the whole unit)" conflation is wrong: the recipients sit in
   the HEADER (hc, recycled), not the payload; the payload commission is the messages (~79 min).
2. E2-11's N=200/1000 rows are impossible: shares are positive integers summing to 100 → N ≤ 100.
3. E2-11's "the creator pays ~50× the max gain" is directionally right (the per-hop loss ≥ 29 =
   ~0.6× the max gain at the quietest; ~30× at rate 1; unbounded at real rates) but the mechanism
   is the minimal-message requirement, not the header/recipient cost.
4. E1-10's "zero-mean" for the settlement floor is imprecise (E2-11 corrected; confirmed here —
   the floor is sign-biased and always destroys).

## Verdict

**CAPPED — no escalation.** Paid-witnessing creation benefits only governance-selected OPs;
headers-commission minting is real in mechanism (+50/payout, recyclable hc, grindable residue)
but economically dead by ≥29 units per hop (mandatory minimal payload commission 79 vs bounded
mint 50). No accumulation. Both remain hardening notes (HN-2 pattern sites), not findings.

## Residual risks

- If the messages requirement were ever relaxed (a future protocol change allowing empty-message
  units), the hc chain becomes a slow value printer (~+31 units/hop at rate 0). Recorded as a
  latent hazard, not a live bug.
- The sha1 winner grind's expected cost with competitors was not re-measured (E1-2 covered the
  hash-control space); irrelevant to the dead economics.
