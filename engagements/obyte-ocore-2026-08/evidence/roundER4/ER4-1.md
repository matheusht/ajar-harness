## Claim (a) — the demotion is correct (honest-author freeze unreachable): VERIFIED

**Decomposition, independently re-derived:**

1. **The count=N window is real and is exactly what a flood produces.** `getFinalTps`
   (`storage.js:1166-1221`) computes `countAll` over **all** units in `(last_ball_mci, mci]`
   (`for (let i = mci; i > last_ball_mci; i--)`, `storage.js:1209-1217`), not just the
   settling unit's ancestors. `last_ball_unit` is a fixed authoring-time field (composer picks
   the last stable MC ball; `validation.js:715-740` only requires existence, MC membership, and
   inclusion in parents — **no "newest ball" requirement**, confirmed by grepping every
   `last_ball` use in validation.js). Decisive raw log: `/tmp/e29-hub.log` per-MCI settlement
   decodes to tps = mci/elapsed with the last ball fixed at genesis (ts 1786457404):

   | mci | log line | tps | decode |
   |---|---|---|---|
   | 6 | 3516 | 1.2 | count=6, elapsed=5 |
   | 17 | 3736 | 2.8333333333333335 | count=17, elapsed=6 |
   | 18 | 3756 | 2.5714285714285716 | count=18, elapsed=7 |
   | 21 | 3816 | 3.0 | count=21, elapsed=7 |
   | 22 | 3836 | 3.142857142857143 | count=22, elapsed=7 |

   Unit timestamps (line 4343: mci 2–6 = 7409, mci 7–17 = 7410, mci 18–22 = 7411; genesis
   7404) reproduce every fraction exactly → last ball fixed at **mci 0**, count = mci,
   count=22 at mci 22. E4-1's table is byte-exact.

2. **The honest author's elapsed cannot be 1.** Honest units get wall-clock timestamps
   (`composer.js:360` full-node path, `:353` light path — E4-1's citation exact). Validation
   bounds only the future (`validation.js:280-285`, `≤ now+5`) and allows `ts == parent_ts`
   equality (`validation.js:690-693`), but no rule forces an honest author to backdate. The
   ball an honest unit references is already stable/balled at authoring time, so
   `elapsed = mc_ts − last_ball_ts ≥ balling latency` (measured 4–7 s in the lab, line 4343
   decoding; larger with 12 mainnet witnesses). The equal-timestamp lever is attacker-only.

3. **Settlement debit lands on the author's own address.** `updateTpsFees` computes
   `total_tps_fees_delta = (tps_fee || 0) − tps_fee_final` (`storage.js:1249`) and REPLACEs
   `tps_fees_balance` per recipient (`storage.js:1258-1261`) — a flood-chain debit hits the
   attacker's own balance (**self-frosting, zero collateral**). Cross-author collateral needs an
   honest unit authored within ~1 s of a just-balled unit: not observed (4–7 s) and structurally
   gated by balling latency. The funding bound (`validation.js:2653` inputs must cover declared
   fee — E4-1 cites 2654-2655, actual 2653, cosmetic) caps deep attacker chains (fee ~
   `10·(e^k−1)` exceeds TOTAL_WHITEBYTES=1e15, `constants.js:15`, at k≈33; exp-overflow at
   k≥710 is beyond that cap).

4. **Demotion record is present and the honest-freeze impact claim is genuinely dead.**
   `unproven/obyte-2026-08-004/REPORT.md` §REFUTATION/DEMOTION (lines 83-91) demotes the package
   to unproven with the wrong mechanism rationale (see claim b); the measured honest-author fees
   are 8–10 orders of magnitude below the 10.7%-of-supply figure under any parameter reading
   (0–1 base observed; ≤ ~2,437 base at the peak waypoint even at true mainnet `tps_interval=1`,
   re-derived below). No freeze; worst case is micro-GBYTE repayable debt.

**Verdict: verified.**

## Claim (b) — M1 correction: count=1 "always" was too strong; protections are M2 + funding bound + self-frosting: VERIFIED

- **E3-10's M1 conclusion is wrong.** E3-10 claims the count>=30 state "the pinned stabilization
  never creates" (E3-10 M1 + residual note #1; echoed in REPORT.md:90-91 "synthesized — the
  pinned stabilization never produces it" and the "count walk (storage.js:1186-1200) counts 1"
  claim). E2-9's **own** raw log disproves it: count=22 with the last ball at mci 0 (decode
  above). The 1-MCI-at-a-time advance (`main_chain.js:470,501-508` "not trying next any more"
  at 505 → `finish()` → `updateTpsFees(arrStabilizedMcis)` at 448-451; `writer.js:715-718`,
  `742-744` one-MCI-per-pass throws — all line-cited correctly by E4-1) changes **when** a unit
  settles, not **which** ball it references.
- **E4-1's correction is right on the mechanism:** the reachable part is the count dimension
  (flood shape); the unreachable part is `elapsed=1` for an honest author (M2).
- **M2 verified independently:** composer wall-clock (above), honest-unit S3 = **4,917 base**
  re-derived exactly (`round(10·(e^6.2−1))` = 4917, node re-check), E2-9's elapsed 4–7 s decode.
- **r2-drive critique verified:** `evidence/round1/r2-tps-fee-drive.js` — `mkUnit()` sets
  `timestamp: T` for **every** unit including the honest one, and fixes `last_ball_unit:
  "lastball"` (mci 0, ts=T) for all → the honest unit settles with elapsed `(T−T)||1` = 1 and
  count=31, i.e. the attacker's trick applied to the honest author. E4-1's §4 is accurate.
- **New caveat (not in E4-1 or E2-9): the E2-9 settlement ran at `tps_interval=60`, not the
  claimed mainnet `tps_interval=1`.** The lab boot seeds `tps_interval=60` (`e17b-boot.js:92`);
  `getSystemVar` reads only the in-memory cache loaded once at boot (`storage.js:1122-1126`,
  `initSystemVars` `storage.js:2462-2473`); `e29-run.js`'s `UPDATE system_vars SET
  value='1'` never refreshes that cache. All 24 observed `actual_tps_fee` values match
  `round(10·(e^(tps/60)−1))` **exactly** and do NOT match `tps_interval=1` (checked digit by
  digit: match@60 = true, match@1 = false). Consequences:
  - E2-9's "mainnet values" framing and "no negative balances anywhere" / "10× multiplier
    credits (not debits)" are **lab-parameter artifacts**: at true mainnet `tps_interval=1`
    the same run yields fees of ~5–191–222 base for the burst (mci 21/22) and ~2,437 base for
    the WP-2 waypoint, driving the user balance to −9/−220 base and the witness to ≈ −2,432
    base at the peak — micro-GBYTE repayable debt, **not** a freeze (10.7% of supply =
    1.07e14 base ≈ 9-10 orders larger). E2-9's *conclusion* survives; its *intermediate
    numbers* do not.
  - The tps values themselves (`tps = count/elapsed`) and the elapsed decode are
    interval-independent, so the count=22 and M2 measurements stand.
- **Funding bound + self-frosting verified** (above, claim a items 3).

**Verdict: verified — E4-1's correction is correct as written; add the tps_interval-cache note
to E2-9/E3-10 (presentation only).**
