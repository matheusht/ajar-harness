# OpenCode v2.0.32 exclusive trust research

Date: 2026-10-21

## Conclusion

The current `SSL_CERT_FILE=/fixture/runtime-ca.pem` plan is not an exclusive trust store for the pinned OpenCode runtime. The official OpenCode v2.0.32 build embeds Bun's `--use-system-ca` option. Bun 1.4.2 constructs that native default store by adding its bundled roots, OpenSSL default roots, `NODE_EXTRA_CA_CERTS`, and then system roots. `SSL_CERT_FILE` and `SSL_CERT_DIR` can change some inputs to that union, but they cannot remove Bun's bundled roots.

The source-supported replacement mechanism identified for native `fetch` is `fetch(url, { tls: { ca } })`. Bun's type contract says an explicit `ca` completely replaces Mozilla's roots, and its native TLS implementation puts a nonempty explicit CA set into the new context's initially empty store. OpenCode v2.0.32 does not expose that option through its JSON provider configuration or session HTTP hooks.

The smallest supportable design is a source-pinned OpenCode rebuild that adds host-validated, runtime-bounded nonempty CA bytes to the existing `FetchHttpClient.RequestInit` used by native HTTP inference. Qualification must reject AI SDK or custom providers and WebSocket transport before the selected model dispatch opens a provider-transport socket. Other OpenCode egress is outside this seam and must be separately suppressed or contained. This design still needs the owned dual-chain runtime check below. Source inspection alone does not qualify it.

## Trust mechanisms in Bun 1.4.2

The exact Bun source used here is tag `bun-v1.4.2`, commit [`744846f844374847c902b5e7fd59b4342a51ef99`](https://github.com/oven-sh/bun/tree/744846f844374847c902b5e7fd59b4342a51ef99).

| Mechanism | Exact source behavior | Exclusive supplied-only trust? |
| --- | --- | --- |
| OpenCode's compiled `--use-system-ca` | Bun accepts the system, OpenSSL, and bundled mode flags as mutually exclusive choices ([argument definitions and validation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L267-L270), [mode selection](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L1458-L1493)). The native default store first adds bundled roots and OpenSSL defaults, then extra roots, and adds system roots when system mode is active ([store construction](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L294-L346)). | No. System mode adds roots to the default union. |
| `SSL_CERT_FILE` and `SSL_CERT_DIR` | On POSIX, the system loader reads the named file and directories. An empty value disables that particular system source ([system loader](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/socket/system_certs.rs#L197-L248)). The OpenSSL default-file loader also honors `SSL_CERT_FILE` ([file loader](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/socket/cert_files.rs#L42-L62)). | No. Even if both variables suppress every ambient file and directory, native default-store construction has already added Bun's bundled roots. |
| `NODE_EXTRA_CA_CERTS` | Bun reads the named file once, then appends each certificate to the native default store after the bundled and OpenSSL inputs ([load](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L175-L185), [append](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L328-L344)). | No. It is additive. |
| `--use-bundled-ca` or `--use-openssl-ca` | These mode flags do not accept a supplied CA. Bun rejects more than one CA mode, and this OpenCode executable already embeds system mode ([Bun parser](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L1458-L1468), [OpenCode build](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/script/build.ts#L181-L187)). Bun's `--ca` and `--cafile` options belong to its package-manager command, not the general runtime parser ([package-manager arguments](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/install/PackageManager/CommandLineArguments.rs#L64-L74)). | No supported CLI route exists in this artifact for a supplied-only store. |
| `tls.setDefaultCACertificates()` | Bun 1.4.2 says it has no equivalent native store override. Its implementation keeps a JavaScript-side override for `getCACertificates("default")` and `createSecureContext()` ([implementation note](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/js/node/tls.ts#L1762-L1777)). | No for native `fetch`. |
| `fetch(..., { tls: { ca } })` | `BunFetchRequestInit.tls` extends `Bun.TLSOptions` ([fetch types](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-types/globals.d.ts#L1930-L1953)). The `ca` contract says explicit CAs completely replace Mozilla's CAs ([TLS type](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-types/bun.d.ts#L4623-L4667)). Native context creation installs a nonempty explicit `ca` in the context's initially empty store and uses the shared default store only when no user CA exists ([native implementation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/openssl.c#L1351-L1404)). | Yes by source contract for a nonempty, valid explicit CA. The exact OpenCode path still needs an owned runtime test. |

An empty `tls.ca` must not reach Bun. The native branch applies exclusive handling only when `ca_count > 0`; otherwise it selects the shared default store ([native implementation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/openssl.c#L1375-L1404)). Host preparation must retain its hash, certificate-only, path, and size validation. The runtime seam must independently reject a missing, unreadable, empty, or oversized input before the native inference executor can dispatch the selected provider request. Passing those checks is not a claim that the seam fully parses X.509; Bun's explicit-CA context creation remains the parser.

## OpenCode integration boundary

OpenCode's native HTTP inference path already has a central Bun request-init point. `app-node-platform.ts` provides `{ timeout: false } as BunFetchRequestInit` to `FetchHttpClient`, builds the global `RequestExecutor` from that client, and builds `LLMClient` from the executor ([platform layer](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/effect/app-node-platform.ts#L9-L27)). `RequestExecutor.layer` sends native route requests through the injected HTTP client ([executor](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/executor.ts#L237-L262)).

OpenCode pins Effect 4.0.1 ([dependency pin](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/package.json#L76-L84)). At Effect 4.0.1's tagged commit `460272d30457f4697d8b8c52cad41caccbcace08`, `FetchHttpClient` reads the contextual `RequestInit` object and spreads it into the call to global `fetch`; it then replaces only the request method, headers, body, duplex, and signal ([Effect implementation](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/http/FetchHttpClient.ts#L52-L76)). Bun's nonstandard `tls` member therefore reaches native `fetch` in this exact dependency version. Effect labels this module unstable, so a future dependency update requires source review and a new owned check ([module status](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/http/FetchHttpClient.ts#L1-L10)).

The reviewed config selects `opencode/deepseek-v4.1-flash-free` ([local config](smoke/opencode_v2_live_config.json)). The v2.0.32 catalog records the `opencode` host as `@ai-sdk/openai-compatible` and includes that free model ([catalog snapshot](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev/snapshot.txt#L1)). Catalog normalization calls the native-package mapper ([normalization](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L85-L93)), which maps `@ai-sdk/openai-compatible` to `@opencode/ai/providers/openai-compatible` ([mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/aisdk-native.ts#L56-L77)). The model resolver sends only packages still marked with the `aisdk:` prefix to the separate AI SDK loader and loads the mapped package through the native path ([resolver](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/model-resolver.ts#L196-L224)). Exact package and transport readback remain acceptance requirements because configuration transforms can change them.

No published configuration switch carries a function or Bun TLS object into that native route. Core removes `fetch` from native provider settings ([provider settings](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/provider.ts#L186-L195)). Session HTTP hooks round-trip a Web `Request`, whose standard `RequestInit` cannot carry Bun's nonstandard `tls` member ([hook path](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/model-request.ts#L337-L365)). The existing observer hook therefore cannot enforce exclusive trust.

Two paths bypass the native HTTP seam:

- AI SDK providers install a separate direct-fetch wrapper and choose a captured custom fetch or global fetch ([AI SDK path](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/aisdk.ts#L121-L176)).
- WebSocket model transport uses the runtime trust store. OpenCode's Bun WebSocket constructor explicitly keeps `NODE_EXTRA_CA_CERTS` additive and supplies no per-connection CA ([WebSocket constructor](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/effect/websocket-constructor.ts#L58-L78)). Session preparation selects this separate transport when the model requests WebSocket ([transport selection](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/model-request.ts#L366-L397)).

The [prepared source patch](patches/opencode-v2.0.32-exclusive-ca.patch) requires the pair `OPENCODE_EXCLUSIVE_CA_FILE=/fixture/runtime-ca.pem` and `OPENCODE_EXCLUSIVE_CA_SHA256=<64 lowercase hex>`. When the native request-executor layer is acquired, it fails if either variable is missing or invalid. It opens the fixed path once with `O_NOFOLLOW`, bounds and reads that descriptor, verifies stable file metadata and the required digest, sets `rejectUnauthorized: true`, and adds `tls: { ca: replacementCaBytes }` beside the existing `timeout: false` at the native request-init point. Qualification must show that no later request option replaces those TLS fields and reject conflicting input or route selection. The exact package and HTTP-transport predicate must be read and enforced from the same process and resolved model snapshot that performs dispatch. Both the sole matching provider and model must expose the owned base URL, the provider must select HTTP, and the model must have no transport override before the selected provider request can open a socket.

Do not claim process-wide exclusive trust. OpenCode's model-catalog refresh constructs another HTTP client and fetches `${source}/api.json` outside the patched inference executor ([catalog client and fetch](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L309-L352)); startup forks that refresh on a schedule ([refresh scheduling](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L432-L435)). That traffic, along with console, tool, AI SDK, custom-provider, and WebSocket traffic, must be separately suppressed or contained unless it is adapted and tested.

The prepared checker disables catalog fetches and keeps each core arm's readback and dispatch in one loopback-only server process on an internal Docker bridge. OpenCode requires a nonempty server lease value even on loopback. A later run therefore also requires explicit authority for 13 per-container ephemeral leases: each is generated inside the foreground `opencode serve` process boundary, retained only in bounded process environments, excluded from Docker configuration, arguments, files, logs, and receipts, protected from core dumps, and destroyed through exact container cleanup. The checker uses OpenCode's internal `default` server-process mode rather than persistent managed-service mode. No such lease or runtime has been created during source preparation.

## Required owned runtime proof

Prepare this check as source and fixtures only until its runtime action receives separate approval:

1. Generate one-run ambient CA A and replacement CA B plus leaf certificates for the same owned test hostname. Supply CA A only through the isolated arm's declared `SSL_CERT_FILE` ambient-control path. Mount CA B at the hash-pinned replacement path and set the exact paired path and digest variables only in the patched arms. Do not modify the host or base image trust store.
2. In an exact unpatched OpenCode v2.0.32 control image, require the CA A server to succeed through default trust. The published source recipe pins Bun 1.4.2, but the eventual image receipt must independently bind that build identity. The control result proves the ambient-only chain is usable rather than malformed.
3. In the derived OpenCode process with ambient CA A and replacement CA B, require the CA B server to complete the benign synthetic request. Against the CA A server, require TLS verification failure and zero HTTP requests on every bounded attempt.
4. Record responder-side TCP/TLS failure counts and HTTP request counts. Permit only the predeclared bounded negative attempts. Reject an alternate authority, another transport, or a fallback that reaches HTTP. Also reject AI SDK packages and `transport=websocket` before the selected provider transport opens a socket.
5. Run both variables absent, missing path variable, missing digest variable, malformed digest, wrong path, fixed-but-missing path, unreadable file, empty file, oversized file, wrong digest, malformed certificate, and mixed key-and-certificate cases. The host preparation checks must reject path, hash, certificate-only, and size failures before output creation, Docker, or a network syscall. The runtime seam must independently reject its paired-variable, path, read, size, stability, and digest failures before selected native provider dispatch opens its socket. Retain only hashes, fixed error codes, counts, source and image identities, and cleanup results.

No external or live provider/model service call is part of this proof. The synthetic owned route is deliberately exercised. This does not remove `cloud_live_route_not_qualified`, change system or container trust, qualify the managed sidecar, or change the issue #165 no-go decision.
