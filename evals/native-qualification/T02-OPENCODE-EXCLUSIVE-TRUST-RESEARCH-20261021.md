# OpenCode v2.0.32 exclusive trust research

Date: 2026-10-21

## Conclusion

The current `SSL_CERT_FILE=/fixture/runtime-ca.pem` plan is not an exclusive trust store for the pinned OpenCode runtime. The official OpenCode v2.0.32 build embeds Bun's `--use-system-ca` option. Bun 1.4.2 constructs that native default store by adding its bundled roots, OpenSSL default roots, `NODE_EXTRA_CA_CERTS`, and then system roots. `SSL_CERT_FILE` and `SSL_CERT_DIR` can change some inputs to that union, but they cannot remove Bun's bundled roots.

The source-supported replacement mechanism identified for native `fetch` is `fetch(url, { tls: { ca } })`. Bun's type contract says an explicit `ca` completely replaces Mozilla's roots, and its native TLS implementation puts a nonempty explicit CA set into the new context's initially empty store. OpenCode v2.0.32 does not expose that option through its JSON provider configuration or session HTTP hooks.

The smallest supportable design is a source-pinned OpenCode rebuild that adds host-validated, runtime-bounded nonempty CA bytes to the existing `FetchHttpClient.RequestInit` used by native HTTP inference. Qualification must reject AI SDK or custom providers and WebSocket transport before the selected model dispatch opens a provider-transport socket. Other OpenCode egress is outside this seam and must be separately suppressed or contained. This design still needs the owned dual-chain runtime check below. Source inspection alone does not qualify it.

## Trust mechanisms in Bun 1.4.2

The exact Bun source used here is tag `bun-v1.4.2`, commit [`744846f844374847c902b5e7fd59b4342a51ef99`](https://github.com/oven-sh/bun/tree/744846f844374847c902b5e7fd59b4342a51ef99).

| Mechanism | Exact source behavior | Exclusive supplied-only trust? |
| --- | --- | --- |
| OpenCode's compiled `--use-system-ca` | Bun accepts the system, OpenSSL, and bundled mode flags as mutually exclusive choices ([argument definitions and validation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L267-L270), [mode selection](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L1458-L1493)). The native default store first adds bundled roots and OpenSSL defaults, then extra roots, and adds system roots when system mode is active ([store construction](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L294-L346)). | No. System mode adds roots to the default union. |
| `SSL_CERT_FILE` and `SSL_CERT_DIR` | On POSIX, the system loader reads the named file and directories. An empty value disables that particular system source ([system loader](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/socket/system_certs.rs#L197-L248)). The OpenSSL default-file loader also honors `SSL_CERT_FILE` ([file loader](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/socket/cert_files.rs#L42-L62)). | No. Even if both variables suppress every ambient file and directory, native default-store construction has already added Bun's bundled roots. |
| `NODE_EXTRA_CA_CERTS` | Bun reads the named file once, then appends each certificate to the native default store after the bundled and OpenSSL inputs ([load](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L175-L185), [append](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/root_certs.cpp#L328-L344)). | No. It is additive. |
| `--use-bundled-ca` or `--use-openssl-ca` | These mode flags do not accept a supplied CA. Bun rejects more than one CA mode, and this OpenCode executable already embeds system mode ([Bun parser](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/runtime/cli/Arguments.rs#L1458-L1468), [OpenCode build](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/script/build.ts#L181-L187)). Bun's `--ca` and `--cafile` options belong to its package-manager command, not the general runtime parser ([package-manager arguments](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/install/PackageManager/CommandLineArguments.rs#L64-L74)). | No supported CLI route exists in this artifact for a supplied-only store. |
| `tls.setDefaultCACertificates()` | Bun 1.4.2 says it has no equivalent native store override. Its implementation keeps a JavaScript-side override for `getCACertificates("default")` and `createSecureContext()` ([implementation note](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/src/js/node/tls.ts#L1762-L1777)). | No for native `fetch`. |
| `fetch(..., { tls: { ca } })` | `BunFetchRequestInit.tls` extends `Bun.TLSOptions` ([fetch types](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-types/globals.d.ts#L1930-L1953)). The `ca` contract says explicit CAs completely replace Mozilla's CAs ([TLS type](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-types/bun.d.ts#L4623-L4667)). Native context creation installs a nonempty explicit `ca` in the context's initially empty store and uses the shared default store only when no user CA exists ([native implementation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/openssl.c#L1351-L1404)). | Yes by source contract for a nonempty, valid explicit CA. The exact OpenCode path still needs an owned runtime test. |

An empty `tls.ca` must not reach Bun. The native branch applies exclusive handling only when `ca_count > 0`; otherwise it selects the shared default store ([native implementation](https://github.com/oven-sh/bun/blob/744846f844374847c902b5e7fd59b4342a51ef99/packages/bun-usockets/src/crypto/openssl.c#L1375-L1404)). Host preparation must retain its hash, certificate-only, path, and size validation. The runtime seam must independently reject a missing, unreadable, empty, or oversized input before the native inference executor can dispatch the selected provider request. Passing those checks is not a claim that the seam fully parses X.509; Bun's explicit-CA context creation remains the parser.

## OpenCode integration boundary

OpenCode's native HTTP inference path already has a central Bun request-init point. `app-node-platform.ts` provides `{ timeout: false } as BunFetchRequestInit` to `FetchHttpClient`, builds the global `RequestExecutor` from that client, and builds `LLMClient` from the executor ([platform layer](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/effect/app-node-platform.ts#L9-L27)). `RequestExecutor.layer` sends native route requests through the injected HTTP client ([executor](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/executor.ts#L237-L262)).

OpenCode pins Effect 4.0.1 ([dependency pin](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/package.json#L76-L84)). At Effect 4.0.1's tagged commit `460272d30457f4697d8b8c52cad41caccbcace08`, `FetchHttpClient` reads the contextual `RequestInit` object and spreads it into the call to global `fetch`; it then replaces only the request method, headers, body, duplex, and signal ([Effect implementation](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/http/FetchHttpClient.ts#L52-L76)). Bun's nonstandard `tls` member therefore reaches native `fetch` in this exact dependency version. Effect labels this module unstable, so a future dependency update requires source review and a new owned check ([module status](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/http/FetchHttpClient.ts#L1-L10)).

Effect 4.0.1's `HttpClient.transformResponse` wraps each response effect, not layer construction ([transform implementation](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/http/HttpClient.ts#L311-L328)). The patch therefore defers CA validation to execution of each native HTTP effect and supplies `FetchHttpClient.RequestInit` in that executing fiber. It captures local validation errors with `Effect.try`, normalizes them to a fixed nonsecret marker, and converts the result with `Effect.orDie` ([Effect `orDie`](https://github.com/Effect-TS/effect/blob/460272d30457f4697d8b8c52cad41caccbcace08/packages/effect/src/Effect.ts#L3675-L3687)). This distinction is intentional: the OpenCode request executor maps typed transport failures into its transport-error path, which is retryable, while a defect bypasses that retry policy ([executor error mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/executor.ts#L171-L215), [retry policy](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/runner/retry.ts#L42-L56)). Session error conversion preserves the normalized defect message, while a native TLS failure becomes exact error type `provider.transport` with no HTTP status or response body ([session conversion](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/to-session-error.ts#L28-L40), [provider-error projection](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/to-session-error.ts#L97-L104)). The noninteractive JSON path emits at most the observed `step_start` events, one same-session terminal error, and exit status 1; its one-shot guard prevents duplicate terminal errors ([JSON emitter](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/run/noninteractive.ts#L100-L103), [terminal handling](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/run/noninteractive.ts#L511-L532)). Final projection can omit live step-start records, so only the single terminal error count is fixed; the bounded step-start count is validated and retained but is not retry evidence. Those exact trace shapes remain future runtime assertions, not source-only qualification results.

The reviewed config selects `opencode/deepseek-v4.1-flash-free` ([local config](smoke/opencode_v2_live_config.json)). The v2.0.32 catalog records the `opencode` host as `@ai-sdk/openai-compatible` and includes that free model ([catalog snapshot](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev/snapshot.txt#L1)). Catalog normalization calls the native-package mapper ([normalization](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L85-L93)), which maps `@ai-sdk/openai-compatible` to `@opencode/ai/providers/openai-compatible` ([mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/aisdk-native.ts#L56-L77)). The model resolver sends only packages still marked with the `aisdk:` prefix to the separate AI SDK loader and loads the mapped package through the native path ([resolver](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/model-resolver.ts#L196-L224)). Exact package and transport readback remain acceptance requirements because configuration transforms can change them.

Provider request headers do not belong under `settings`. The configuration schema and loader keep top-level `headers` separate from `settings` ([schema](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/schema/src/config/provider.ts#L34-L37), [plugin mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/config/plugin/provider.ts#L73-L74)). Model construction merges provider and model headers at the top level, and native resolution assigns that merged value to the route settings ([model merge](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/model.ts#L209-L214), [native resolution](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/model-resolver.ts#L225-L230)). The openai-compatible provider carries those headers through its route defaults and client request, and HTTP transport emits them on the request ([provider route](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/providers/openai-compatible.ts#L48-L59), [client mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/client.ts#L147-L159), [HTTP transport](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/transport/http.ts#L52-L68)). The owned checker therefore places its public arm header at `providers.opencode.headers` and requires exact equality in the source document, provider snapshot, and effective merged model snapshot. Echoing `settings.headers` would not prove an outgoing header.

No published configuration switch carries a function or Bun TLS object into that native route. Core removes `fetch` from native provider settings ([provider settings](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/provider.ts#L186-L195)). Session HTTP hooks round-trip a Web `Request`, whose standard `RequestInit` cannot carry Bun's nonstandard `tls` member ([hook path](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/model-request.ts#L337-L365)). The existing observer hook therefore cannot enforce exclusive trust.

Two paths bypass the native HTTP seam:

- AI SDK providers install a separate direct-fetch wrapper and choose a captured custom fetch or global fetch ([AI SDK path](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/aisdk.ts#L121-L176)).
- WebSocket model transport uses the runtime trust store. OpenCode's Bun WebSocket constructor explicitly keeps `NODE_EXTRA_CA_CERTS` additive and supplies no per-connection CA ([WebSocket constructor](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/effect/websocket-constructor.ts#L58-L78)). Session preparation selects this separate transport when the model requests WebSocket ([transport selection](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/model-request.ts#L366-L397)).

The [prepared source patch](patches/opencode-v2.0.32-exclusive-ca.patch) requires the pair `OPENCODE_EXCLUSIVE_CA_FILE=/fixture/runtime-ca.pem` and `OPENCODE_EXCLUSIVE_CA_SHA256=<64 lowercase hex>` when a native HTTP request effect executes. It opens the fixed path once with `O_NOFOLLOW`, bounds and reads that descriptor, verifies stable file metadata and the required digest, sets `rejectUnauthorized: true`, and adds `tls: { ca: replacementCaBytes }` beside the existing `timeout: false` at the native request-init point. Every validation and unexpected internal failure is normalized to `OPENCODE_EXCLUSIVE_CA_REJECT:<fixed-code>`. Qualification must show that no later request option replaces those TLS fields and reject conflicting input or route selection. The exact package and HTTP-transport predicate must be read and enforced from the same process and resolved model snapshot that performs dispatch. Both the sole matching provider and model must expose the owned base URL, top-level provider and merged model snapshots must expose the exact public arm header, the provider must select HTTP, and the model must have no transport override before the selected provider request can open a socket.

The ambient-chain TLS failure is a native HTTP transport failure without rejected-delivery evidence, so OpenCode classifies it as retryable ([transport mapping](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/route/executor.ts#L171-L215), [retryability](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/ai/src/provider-error.ts#L77-L95)). The pinned retry schedule permits ten retries after the initial attempt: jittered gaps derive from 2, 4, 8, then seven 10-second caps, totaling about 67–101 seconds ([policy](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/runner/retry.ts#L42-L90)). Each accepted responder socket has a five-second TLS-operation timeout; responder shutdown is bounded separately. The checker therefore gives only that negative arm a conservative 240-second outer bound, requires exact terminal `provider.transport` evidence from the command session, and requires exactly 11 owned TCP/TLS failures. Source fixes the 11 model attempts; one owned socket per attempt remains a future runtime assertion. Killing the CLI at the ordinary 60-second bound would be a false terminal proof because its persistent server session could still be retrying.

Do not claim process-wide exclusive trust. OpenCode's model-catalog refresh constructs another HTTP client and fetches `${source}/api.json` outside the patched inference executor ([catalog client and fetch](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L309-L352)); startup forks that refresh on a schedule ([refresh scheduling](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L432-L435)). That traffic, along with console, tool, AI SDK, custom-provider, and WebSocket traffic, must be separately suppressed or contained unless it is adapted and tested.

The prepared checker disables remote catalog fetches, starts every container with `NetworkMode=none`, rejects nonempty image `Config.Volumes` and `Config.Healthcheck`, and requires the complete inspected mount list to equal only its requested binds. This closes a nested image-volume path that could otherwise mask the fresh HOME/XDG/config/project source tree while a host check still examined the underlying bind source. It also passes Docker's `--no-healthcheck` override and requires exact disabled-healthcheck readback, excluding an inherited concurrent process with access to the same container namespace. Docker IPAM is configurable, so the checker does not infer private scope from an internal bridge or use Python's broader `is_private` classification: it requires the entire IPv4 subnet to be a subnet of `10/8`, `172.16/12`, or `192.168/16`, then requires distinct in-subnet gateway and endpoint addresses. Pure regressions reject public, shared-space, loopback, and RFC1918-containing supernets.

The Docker CLI supports explicit runtime selection and sets `HostConfig.Runtime` from `--runtime`; it sets the pointer-valued `HostConfig.Init` only when the `--init` flag was explicitly supplied ([flag definitions](https://github.com/docker/cli/blob/6d274590f2f63276a54da8adf475a455d21c1fdd/cli/command/container/opts.go#L309-L322), [host-config construction](https://github.com/docker/cli/blob/6d274590f2f63276a54da8adf475a455d21c1fdd/cli/command/container/opts.go#L700-L727)). The checker therefore supplies `--runtime runc --init=false`, reads both exact values back, and verifies top-level process `Path` and `Args`; a daemon-default init process cannot silently replace the server as PID 1. Absolute shell and OpenCode paths avoid delegating command selection to `PATH` even after its value is pinned. This proves the selected runtime name, not the registered binary: the Docker daemon and its `runc` registration remain trusted readiness prerequisites for any later approved run.

The checker keeps each core arm's readback and dispatch in one loopback-only server process. `opencode api` resolves a named operation through local `/openapi.json` and calls only that local endpoint ([API client](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/commands/handlers/api.ts#L18-L50), [operation resolution](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/commands/handlers/api.ts#L54-L77)). The pinned `server.info`, `provider.list`, `model.list`, and `config.get` handlers return metadata, available definitions, or config entries and do not create a session or call the request executor ([server handler](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/server/src/handlers/server.ts#L16-L28), [provider handler](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/server/src/handlers/provider.ts#L8-L17), [model handler](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/server/src/handlers/model.ts#L8-L17), [config handler](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/server/src/handlers/config.ts#L7-L10)). Default-mode `opencode serve` has no lifecycle object and therefore does not enter the suspended-session resume path ([server mode](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/server-process.ts#L60-L68), [lifecycle gate](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/server/src/process.ts#L107-L111)). By contrast, the noninteractive run creates/selects a session and invokes `session.prompt` only after its prompt is ready ([prompt admission](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/run/noninteractive.ts#L688-L726)).

Creating a fresh run session does not itself set a title ([session creation](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/session-target.ts#L61-L75)). On the first admitted prompt, an untitled root session concurrently starts title generation ([runner gate](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/runner/llm.ts#L166-L181)); that path performs its own model stream and can fall back to the session's primary model ([title request](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/title.ts#L64-L90), [model selection](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/context.ts#L95-L118)). That auxiliary inference would invalidate the exact one-request positive and eleven-attempt negative observations. The supported `--title` option is applied to a new session before `runNonInteractivePrompt` ([option](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/commands/commands.ts#L405-L415), [pre-prompt update](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/run/run.ts#L127-L145)). The checker therefore passes one fixed public title on every run command; its pure argument regression prevents this source-bound control from being dropped.

The location-scoped provider/model calls do lazily build the internal instance and wait for plugin activation, so they are not side-effect-free in the broad sense. `plugins: []` suppresses configured plugin entries but not built-ins. The checker therefore also uses a fresh bind-mounted HOME/XDG/project tree and database, requires exact effective HOME/XDG/TMPDIR values, rejects alternate configuration, database, test-home, model-file/model-URL, simulation, and OTLP exporter inputs, and disables project discovery. Those overrides are real pinned inputs: `OPENCODE_DB` precedes the XDG database path ([database selection](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/database-path.ts#L4-L12)); `OPENCODE_TEST_HOME` precedes the ordinary home ([global paths](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/util/src/global.ts#L15-L18)); and the server passes catalog path/URL and inline config overrides into their loaders ([server options](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/server-process.ts#L112-L129)), where a supplied catalog file wins even with fetching disabled ([catalog population](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L355-L402)). OpenCode also reads `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`, and `OTEL_RESOURCE_ATTRIBUTES` and installs OTLP log/trace exporters when an endpoint exists ([CLI observability input](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/cli/src/index.ts#L128-L135), [OTLP setup](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/util/src/observability/otlp.ts#L63-L101)); all three must therefore be absent in the image and effective container environment. It calls `model.list` before its authoritative provider snapshot, then requires `config.get` to equal one exact normalized document followed by only the expected fresh config-directory source. The normalizer turns the short model string into a provider/model object and omits an empty legacy MCP server map ([model normalization](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/config/normalize.ts#L201-L205), [MCP normalization](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/config/normalize.ts#L266-L304)), so the checker compares the API's exact normalized form rather than the bytes written to disk. That equality excludes provider `apiKey`/`env`, skills, instructions, agents, experimental fields, other providers, configured plugins, and configured MCP. Separate host checks reject global `.agents`/`.claude` and config-root `plugin`/`plugins` discovery trees before and after readback; the latter are otherwise scanned automatically ([plugin scan](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/config/plugin/source.ts#L122-L188)). Built-in OpenCode provider activation returns without its optional Console fetch when no active credential exists ([provider activation](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/plugin/provider/opencode.ts#L185-L240)); model-catalog refresh is scheduled only when fetch is enabled ([catalog gating](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L327-L329), [refresh scheduling](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/models-dev.ts#L432-L435)); and warming invokes generation only from session hooks, while `warming:false` contributes no settings ([warming gate](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/plugin/warming.ts#L19-L55)). Actual provider execution is a separate `llm.stream` path ([execution](https://github.com/anomalyco/opencode/blob/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/core/src/session/runner/step.ts#L66-L107)). This is the pinned no-source-reachable-selected-provider-inference premise under the checker's exact inputs; it is not a claim that startup performs no initialization, and it must be re-reviewed on an OpenCode revision change.

After the network-none readback, the checker attaches only the exact labeled bridge, requires a still-zero snapshot, generates a fresh command prompt marker, and activates that marker only while the responder has zero counters and no active connection. It binds the initial ambient and replacement fixture identities, rechecks the active host CA/leaf/key files across all arms, hashes the actual mounted CAs from each running core container before and after dispatch, and requires the candidate-positive and ambient-rejected rows to carry the same mounted CA hashes as the initial fixture. A public per-arm top-level provider header binds a positive request to its arm. The fresh prompt marker must appear exactly once as a JSON scalar in a positive request body, so delayed pre-dispatch traffic cannot satisfy a positive arm. The negative arm instead requires the same-session terminal `provider.transport` evidence described above together with exact retry/failure counts; that terminal event binds the command session but does not cryptographically label each pre-TLS socket.

After command completion, mounted-CA recheck, and any post-failure readback, the checker removes the exact container by ID and proves absence. It then requires two seconds with no active responder connection or counter change, marks the responder sealed, force-closes tracked raw/TLS sockets, stops the listener through a bounded helper, bounded-waits for the serve thread and tracked workers, rejects any seal-time change, and retains the full nonsecret observation counts. Positive arms require exactly one fully marked request. Before creating its private workspace, the checker durably writes a non-secret run nonce, deterministic resource names, the planned recovery path, and the rule that pass is valid only with checker exit 0. It creates that path at mode 0700, fsyncs its parent, then advances the workspace state. Before each Docker create it records a pending journal entry, then records the exact ID only after it is in the owned-resource set; cleanup requires a one-to-one match between confirmed entries and owned resources. An uncertain create can be reconciled by label but can never produce a passing cleanup result in that run. OpenCode requires a nonempty server lease value even on loopback. A later run therefore also requires explicit authority for 13 per-container ephemeral leases: each is generated inside the foreground `opencode serve` process boundary, retained only in bounded process environments, excluded from Docker configuration, arguments, files, logs, and receipts, protected from core dumps, and destroyed through exact container cleanup. The checker uses OpenCode's internal `default` server-process mode rather than persistent managed-service mode. No such lease or runtime has been created during source preparation.

## Required owned runtime proof

Prepare this check as source and fixtures only until its runtime action receives separate approval:

1. Generate one-run ambient CA A and replacement CA B plus leaf certificates for the same owned test hostname. Supply CA A only through the isolated arm's declared `SSL_CERT_FILE` ambient-control path. Mount CA B at the hash-pinned replacement path and set the exact paired path and digest variables only in the patched arms. Do not modify the host or base image trust store.
2. In an exact unpatched OpenCode v2.0.32 control image, require the CA A server to succeed through default trust. The published source recipe pins Bun 1.4.2, but the eventual image receipt must independently bind that build identity. The control result proves the ambient-only chain is usable rather than malformed.
3. In the derived OpenCode process with ambient CA A and replacement CA B, require the CA B server to complete the benign synthetic request. Against the CA A server, require TLS verification failure and zero HTTP requests on every bounded attempt.
4. Record responder-side TCP/TLS failure counts, HTTP request counts, and per-arm CA hashes. Permit only the predeclared bounded negative attempts. Require the negative command to exit 1 with exactly one terminal same-session `provider.transport` JSON error, discard its message and identifiers, and treat any text, tool, success, HTTP status, response body, second error, or unrelated-session record as failure. Require both candidate arms to match each other and the initial stable fixture identities. Reject an alternate authority, another transport, or a fallback that reaches HTTP. Also reject AI SDK packages and `transport=websocket` before the selected provider transport opens a socket.
5. Run both variables absent, missing path variable, missing digest variable, malformed digest, wrong path, fixed-but-missing path, unreadable file, empty file, oversized file, wrong digest, malformed certificate, and mixed key-and-certificate cases. The host preparation checks must reject path, hash, certificate-only, and size failures before output creation, Docker, or a network syscall. The ten bounded runtime cases must independently prove their paired-variable, path, open, size, and digest rejection markers before selected native provider dispatch opens its socket. Stable-descriptor checks and the fixed `read_failed`, `changed`, and `close_failed` branches remain source-reviewed controls; this checker deliberately does not manufacture a concurrent mutation race or descriptor failure, and its receipt cannot claim dynamic coverage for those branches. Retain sanitized hashes, fixed error codes, counts, schema/status/classification fields, bounded source/network/readback facts, source and image identities, and cleanup results; reject unknown arm fields and never retain raw logs, bodies, error messages, credentials, or private material.

No external or live provider/model service call is part of this proof. The synthetic owned route is deliberately exercised. This does not remove `cloud_live_route_not_qualified`, change system or container trust, qualify the managed sidecar, or change the issue #165 no-go decision.
