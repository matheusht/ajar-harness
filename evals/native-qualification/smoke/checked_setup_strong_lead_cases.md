# Checked-setup strong-lead dismissal cases

Public scenario: `python3 evals/native-qualification/smoke/check_native_engagement_joined_e2e.py --output /tmp/checked-setup-strong-lead.json`; repeat with `--missing-disposition --output /tmp/checked-setup-missing-disposition.json` and `--missing-disposition-continue --output /tmp/checked-setup-missing-disposition-continue.json`. Run from the repository root with Python 3.11+ on a Unix host, a local Docker daemon with `busybox:1.37` already available, Go, OpenSSL, and `ssh-keygen`. These use the checked setup transition and public continuation entrypoint with contained synthetic turns, source execution, review, and owner cleanup when closeout is requested. The setup build uses local Docker; the model turns, source result, reviewer, and owner cleanup are simulated. No provider or target service is used. The expected outcomes are `complete_internal_candidate` with a disposition and `stopped_incomplete` without one. The continuing missing-disposition case first returns `closure_review_required`, then supplies a matching manual acceptance and requires `stopped_incomplete` with cleanup readback. The JSON results include pinned source, review, and closeout hashes plus an event trace. A baseline run against `760eeff7` stopped at `closure_review_required` after turn 2, before review; the first partial fix still stopped at that gate after turn 3 when an ordinary next test was proposed.

Before implementation, the first case must fail at the legacy `closure_review_required` gate when the agent requests review of a `strong_lead: false` checkpoint after a `strong_lead: true` checkpoint. The review packet must contain that false checkpoint. With a disposition, an ordinary next test must receive another native turn under the same allowance, and the final false checkpoint and result should close as an internal candidate. A missing disposition must withhold the accepted closeout request and end incomplete, even if the reviewer otherwise accepts the result. Both cases must keep the manual route's legacy closure gate and must never treat the synthetic receipt as target or provider proof.

Other failure boundaries: changing the reviewed claim or RESULT.md requires fresh review; incomplete review cannot close; a stopped or exhausted run cannot dispatch a reviewer; an uncertain source action cannot be replayed; and stop/cleanup readback remains required. The existing agent review and closeout scenarios cover those boundaries. This case targets the checked-setup transition and strong-lead dismissal specifically.

Second-check race: `python3 evals/native-qualification/smoke/check_strong_lead_review_race.py --output /tmp/checked-setup-changed-review.json` changes the host reviewer receipt after capture, before the controller validates the lead disposition. The run and a retry must return `review_incomplete` with the review marked incomplete and no further model turn. A separate intact review with no disposition must still send one model turn and then require legacy closure review. This focused synthetic controller check reuses a captured review and injects the checked-setup marker in memory. The Docker-backed joined scenario could not be rerun for this follow-up because its local BusyBox image was unavailable.

No-Docker closure and patch-routing check: `PYTHONDONTWRITEBYTECODE=1 python3 evals/native-qualification/smoke/check_native_continuation.py > evals/native-qualification/setup-evidence/native-manual-closure-gate-synthetic-e2e.json`. It exercises stale accepted closure, an already-applied reopen, checked-setup patch review routing, legacy forced stop, and accepted manual closure through the real closeout and synthetic owner/Docker readback. The saved JSON reports 13 passing checks. The joined Docker scenario was not rerun after these changes because the local BusyBox image was unavailable.
