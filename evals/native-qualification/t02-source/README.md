# T02 live-path preparation source

This stable directory identifies the post-transfer source state for the fail-closed OSLIT preparation change. `SOURCE-MANIFEST.json` pins the materialized candidate bytes used by the no-Docker source checks. It is separate from the immutable 20 October transfer ZIP and manifest at `cloud-transfer/t02-20261020/`.

The historical ZIP-root or sidecar manifest remains the default source-check authority. It therefore rejects these post-transfer bytes as drift. Reviewers select this manifest explicitly with `check_v2_cloud_owned_source.py --current-manifest`; its presence never overrides the historical root implicitly. If this source is adopted into a canonical repository manifest, this explicit option and directory can be removed together.

The change adds explicit, hash-pinned runtime CA validation and dormant private-snapshot plumbing, rejects unexpected trust overrides, and makes provider ledger reads safe when no owned offline responder exists. A later source-only addition documents why the initial `SSL_CERT_FILE` plan is not exclusive in OpenCode 2.0.32, carries an exact upstream source patch for execution-time, digest-bound Bun `tls.ca`, and prewrites an owned dual-chain checker. Invalid runtime inputs require one exact session-bound rejection marker from the same still-running server. Containers remain at `NetworkMode=none` through pinned readback-only API calls, then attach only the exact owned bridge immediately before dispatch. Exact normalized config readback and container-environment inspection reject alternate config, database, home, catalog, credential, and plugin-source inputs. Positive evidence requires the supported top-level provider/merged-model header and a fresh command-only body marker. Negative evidence separately requires an exact session-bound terminal `provider.transport` error plus the sealed retry/failure counts. Every preflight and dispatch-baseline counter is published, tracked responder sockets and workers are closed through a bounded seal, and only the post-removal sealed delta is eligible. The managed runner never invokes that checker, and source checks exercise only its pure receipt evaluator. The unconditional `cloud_live_route_not_qualified` denial remains before output creation and Docker.

The source manifest and offline receipts are preparation evidence only. They do not prove the managed sidecar reaches an owned receiver, prove that OpenCode excludes built-in trust roots, prove that the patch builds, qualify a patched image or dual-chain runtime result, qualify live TLS or a provider, complete issues #158 or #161, unblock issues #159, #160 or #162, or change the #165 no-go decision.
