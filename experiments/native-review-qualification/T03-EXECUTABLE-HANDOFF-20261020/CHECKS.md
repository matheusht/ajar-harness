# Executable handoff failure checks, before implementation

20 October 2026. Extend the existing native runner, using the frozen packets and
the existing T02 native configuration. No new target fixture, inference, engagement,
provider route, allowance, hidden case or CI. Preserve the prior runner before editing;
its old inventories describe the old revision. Own only native-review-qualification.

Decision: stage one trusted observer-selected input group per isolated native store.
The simpler alternative, mounting all groups into one fresh session, exposes later
conditions and challenges early. Keep the target source and existing raw observations
as the acceptance evidence; do not derive outcomes from a new synthetic reviewer.

| Failure | Falsifiable check |
| --- | --- |
| Stale or researcher-edited manifest chooses the inputs | Require the existing exact HANDOFF.json digest. Reject even an altered exclusion or file list, before making a packet. |
| Missing or edited source/raw/contrary input | Check every selected file's digest before staging; completed native shell output must match every staged file. Reject changed or absent staged files on verification. |
| Symlink, path escape, or duplicate basename replaces material | Reject these before copying. Use an exact selected file set; reject extra files, even an observer answer. |
| Expected answer, old chats, or later phase is visible | Mount only this group's exact copied files plus its generated request, not the observer manifest or parent directory. Inspect actual mount inventory. Every group starts a separate workspace/container with an empty store and empty newly created context. |
| Request binds only the prose claim | Bind the complete selected source/claim/raw file map and group to one input digest, then bind request bytes separately. Keep the frozen source/claim documents unchanged. |
| v1 handoff becomes an invented accepted v1 review | Prior attachment is explicitly a prepared request, with no review verdict. v2 requires an actual prior review and re-review. Old and new input IDs must differ; source may remain identical while claims/policy/raw change. Preserve prior request by digest and valid historical bytes. |
| Lead relabel/drop erases useful unfinished work | Copy exact claim text and its file digest into pending work. A stop derives a saved unfinished state with all claim documents/bases/conditions/next checks unchanged and no disposition verdict. This is mechanical retention, not a model decision or producer-stop test. |
| Offline readiness authorizes inference or resets spend | No inference command in this runner. Shared allowance is unaccepted and has no invented zero/remaining balance. Record exact future prompt, native session ID and input identity; T02 must supply the same accepted original pool before dispatch. |
| Direct API shell is called reviewer work | Label host-issued session.shell and generated requests as assisted preparation. No model-selected causal replay, actual reviewer input consumption, outcome or charge is claimed. |
| Failure evidence, raw paths or resources disappear | Keep every attempted receipt, exact code/config/input hashes and private raw capture. Redact durable home/temp prefixes. Remove only exact owned IDs and temporary state, verify absence. No global Docker cleanup. |

Prewritten executable checks: check_handoff.py exercises the real preparation path
on v1 and v2, tampered manifest/file, missing file, extra answer and retained stop.
Then run offline_context_e2e.py separately for v1, v2 and the existing strong-lead
group, each with a new output directory. The actual v1 request may be attached to
v2 as preparation history; never pass it off as an actual reviewer result.

Expected: transfer/version/retention checks pass, native stores initially empty,
all allowed bytes accessible read-only, no inference and exact cleanup. #159 stays
open until the fresh actual reviewer, causal check, independent effect/control,
shared allowance/cost and changed-claim behavior are observed. #162 stays gated.
