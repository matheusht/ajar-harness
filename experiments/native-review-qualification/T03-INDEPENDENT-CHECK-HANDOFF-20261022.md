# T03 independent-check handoff: failure cases before code

This is a provider-free #159/#162 preparation, not native review qualification. The decision is to pass the exact invocation to the host-owned `independent_check` callback. Its former `(tools, request)` arguments could not bind an app effect to the reviewer dispatch or session. The simpler alternative is to keep `independent_check=None`; that correctly holds every review and remains the current runner behavior. A positive result requires a separately qualified native request origin and a same-claim clean-original replay with a causal control. Neither producer exists in the current runner, so adding a held-only checker would duplicate the current gate without qualifying any new evidence.

| Failure condition | Required provider-free check |
| --- | --- |
| No capture plan or reviewer target, wrong run/session/role/dispatch, symlinked or changed host record | The future host callback must return `held` without reading model prose as evidence. It must bind the exact acknowledged reviewer dispatch to its immutable pre-dispatch bytes, window and origin-gate receipt. Passing the invocation is necessary for this check but does not itself prove the binding. |
| Native trace says a shell tool succeeded, or the reviewer prints success, but no app-side same-operation evidence exists | Keep `native_action_reached_clean_target` absent. A tool event and host replay do not establish which process issued the protected request. |
| A self-consistent window or collector row is presented as native origin | Keep held while the current origin gate returns `native_request_attributable:false`; never convert its `held` status to `observed`. |
| Collector final rows or historical S10 replay are used as the reviewer’s clean replay/control | Keep held. The current adapter records a pre-dispatch prefix and a final aggregate, not a post-dispatch closed effect window or a reviewer-specific clean replay/control receipt. |
| Claim/evidence/source version, reviewer target, actor, build, resource or timing changes | Require a future host receipt to bind all of them before any positive callback. A stale or unrelated receipt must not be promotable by a changed packet or model text. |
| Strong lead is relabeled as irrelevant, or one branch is refuted while another remains viable | The host gate never decides lead disposition from text. `fresh_review` and the operator must retain raw contrary material, supported bases, missing transitions and unfinished next checks. |

The provider-free CLI smoke is `PYTHONDONTWRITEBYTECODE=1 python3 experiments/native-review-qualification/check_fresh_review_setup.py`. It creates a temporary sealed handoff, injects a fake successful tool and model proposal, and requires the host callback to receive the exact invocation while a held response remains `unfinished`. A live native review with independently captured original effect, clean replay/control, exact claim version, and cost remains the falsifier for a later positive implementation. No current synthetic fixture yields `candidate_for_operator_review`.
