# Domain Pack: EVM and Solidity

Load this pack only when `skill_mode=domain` on an EVM/Solidity task.

**Step-2 Divergence Exit Rule:** For any pattern below, inspect the target's actual state transitions and modifiers first. As soon as you verify a concrete compensating control at a real `file:line`, stop pursuing the checklist item and close the task with `ajar task dry <task_id> --worker <id> --locus <file:line> --control "<reason>"`.

## Local Tooling Workflow

Run Foundry and Slither directly inside the isolated worktree or local Anvil fork (no live mainnet/testnet RPC broadcasts):

```bash
forge build
forge test --match-test <test_name> -vvv
anvil --fork-url "$ARCHIVE_RPC_URL" --fork-block-number <pinned_block>
slither . --json -
```

Treat Slither output strictly as surface discovery; never propose a claim from static analyzer output without tracing state reachability.

## Contrastive Pattern Matrix

| Pattern | Defect Pattern & Sinks | Compensating Control That Makes It Safe | 4-Arm Verification Recipe |
| --- | --- | --- | --- |
| **1. Classic State Reentrancy** | External call (`.call{value:...}`, ERC-777/ERC-721 `onERC721Received`, ERC-1155 hook, untrusted token callback) executes before internal balance, debt, or position state updates (`benchmarks/foundry/jpegd-reentrancy`). | `nonReentrant` mutex covers all mutually recursive functions **or** strict Checks-Effects-Interactions updates storage before the external call, or token whitelist restricts assets to pure non-hook ERC-20s. | Arm 1: Callback re-enters and drains/double-mints (`> 0` net attacker profit). Arm 2: Standard deposit/withdraw succeeds. Arm 3: Add `nonReentrant` or move state write before `.call`; exploit reverts/fails. Arm 4: Standard user flow still passes. |
| **2. Read-Only Reentrancy (Price Manipulation)** | Consumer protocol reads pool `get_virtual_price()`, reserve ratios, or LP share value while an upstream pool is mid-`remove_liquidity` / native-ETH callback with out-of-sync balances and totalSupply (`benchmarks/foundry/curve-readonly-reentrancy`). | Upstream pool lock check (`remove_liquidity(..., [0,0])` / reentrancy lock view guard) on the oracle read, or TWAP/heartbeated Chainlink feed unaffected by intra-tx spot state. | Arm 1: Callback borrows/liquidates against inflated `get_virtual_price()` for net profit. Arm 2: Normal borrow/repay succeeds. Arm 3: Reentrancy-check wrapper in oracle blocks mid-callback read. Arm 4: Normal oracle read and borrow succeed. |
| **3. First-Depositor / ERC-4626 Share Inflation** | `_convertToShares` computes `assets * totalSupply / totalAssets` where `totalAssets` includes direct token `transfer` donations (`balanceOf(address(this))`) and zero virtual shares/dead shares exist (`benchmarks/foundry/erc4626-first-depositor`). | OpenZeppelin v4.9+ virtual shares/assets (`_decimalsOffset()`), Uniswap V2 `MINIMUM_LIQUIDITY` dead-share burn at initialization, internal tracked accounting ignoring direct `transfer` donations, or constructor seed deposit. | Arm 1: Attacker mints 1 wei share, donates assets, victim deposit rounds to `0` shares, attacker redeems net profit. Arm 2: Multi-user deposits without donation mint proportional shares. Arm 3: Virtual shares/internal accounting makes attacker PnL `<= 0`. Arm 4: Normal vault deposits/redeems pass. |
| **4. Accounting Invariant Drift** | Mint/burn, fee accrual, debt index update, or reward checkpoint modifies individual user state without matching global accumulator update (or vice versa), letting sequential claim/transfer double-count rewards or strand solvency. | Global and per-user accumulators update atomically before every balance transfer (`_beforeTokenTransfer` / `_update`), and solvency invariant `sum(claims) <= balance` holds across self-transfers. | Arm 1: Self-transfer or split-account sequence extracts more tokens than deposited + accrued. Arm 2: Single-account stake/claim earns expected yield. Arm 3: Sync user reward debt before balance mutation. Arm 4: Single-account stake/claim unchanged. |
| **5. Rounding Direction & Precision Loss** | Division before multiplication or rounding in the caller's favor (`Math.Rounding.Down` on debt/mint cost; `Up` on withdrawal/redeem payout) lets repeated dust operations extract value. | Protocol consistently rounds **against** the caller (down on shares minted / assets withdrawn; up on assets deposited / shares burned) and enforces minimum operation sizes. | Arm 1: `N`-step loop or dust mint/redeem extracts positive net asset delta. Arm 2: Standard-sized deposit/redeem preserves vault solvency. Arm 3: Flip `mulDiv` rounding direction in protocol's favor. Arm 4: Standard deposit/redeem passes within 1-wei tolerance. |
| **6. Broken Access Control & Unprotected Initializers** | Missing caller check on privileged setter/sweep/pause, or upgradeable implementation leaves `initialize()` callable directly (missing `_disableInitializers()` in constructor). | Role modifier (`onlyOwner` / `onlyRole`) guards all privileged entrypoints, implementation constructor calls `_disableInitializers()`, and proxy admin cannot collide with user selectors. | Arm 1: Unprivileged EOAs call setter/initializer and seize role or funds. Arm 2: Authorized owner executes admin config cleanly. Arm 3: Add `onlyRole` / `_disableInitializers()`. Arm 4: Authorized owner flow still passes. |
| **7. `delegatecall` & Proxy Storage Collision** | Arbitrary target/calldata passed to `delegatecall`, uninitialized UUPS `_authorizeUpgrade`, or upgraded storage layout reorders/inserts slots ahead of base contract variables. | `delegatecall` target is immutable/governance-timelocked, EIP-1967 storage slots isolate proxy admin/implementation, and storage gaps preserve layout compatibility. | Arm 1: Unprivileged caller overwrites slot / selfdestructs / hijacks implementation. Arm 2: Authorized upgrade or normal proxy call succeeds. Arm 3: Restrict `delegatecall` target or guard `_authorizeUpgrade`. Arm 4: Normal proxy call passes. |
| **8. EIP-712 / Permit Signature Replay & Malleability** | Off-chain signature verifier omits `nonce`, `chainid`, `address(this)`, `deadline`, or dynamic struct array hashes, or accepts `ecrecover(...) == address(0)` when signer is unset. | EIP-712 domain separator binds `(chainId, verifyingContract)` dynamically on fork, monotonically increments per-signer nonce, enforces `signer != address(0)`, and uses `ECDSA.recover` (`s`-malleability check). | Arm 1: Replay consumed signature, cross-contract signature, or zero-address signature to move funds. Arm 2: Fresh valid signature executes once. Arm 3: Increment nonce + reject `address(0)` + bind domain. Arm 4: Fresh valid signature executes once. |
| **9. Flash-Loan Governance & Spot-Balance Privileges** | Governance quorum/proposal execution, fee tier, or collateral valuation reads current-block `balanceOf` or `getReserves()` instead of prior-block checkpoints (`getPastVotes`). | `ERC20Votes` / `Checkpoints` snapshot at `block.number - 1` (proposal creation block) plus execution timelock, or manipulation-resistant TWAP/Chainlink oracle. | Arm 1: Single-tx flash loan acquires voting power/spot price, passes/executes privileged action, repays loan. Arm 2: Multi-block staked voter executes proposal normally. Arm 3: Switch `getVotes` -> `getPastVotes(account, snapshotBlock)`. Arm 4: Multi-block governance test passes. |
| **10. Missing Slippage (`amountOutMin = 0`) & Expired Deadlines** | Contract swaps, rebalances, or liquidates through an AMM with hardcoded `amountOutMin = 0` or `deadline = block.timestamp`, exposing protocol or user funds to deterministic sandwich extraction. | Caller-supplied or oracle-derived `minAmountOut` and caller-supplied `deadline` enforced at execution, or execution restricted to private/off-chainRFQ settlement with signed quote floor. | Arm 1: Simulated mempool sandwich (`front-run -> victim tx -> back-run` in Foundry) extracts victim value beyond fee tolerance. Arm 2: Unsandwiched swap settles at fair pool price. Arm 3: Enforce oracle/caller `minAmountOut` check (front-run causes victim tx to revert safely). Arm 4: Unsandwiched swap passes. |
| **11. Unchecked Low-Level Call & Silent ERC-20 Return** | Raw `.call(...)` / `.send(...)` ignores boolean `success`, or non-reverting ERC-20 `transfer`/`transferFrom` returns `false` while internal accounting credits the deposit/liquidation. | `SafeERC20.safeTransfer` / `safeTransferFrom` and explicit `require(success)` on every low-level call. | Arm 1: Returning-`false` ERC-20 or failing `.send` credits shares/clears debt without moving tokens. Arm 2: Compliant transfer moves tokens and updates state. Arm 3: Replace with `SafeERC20` / `require(success)`. Arm 4: Compliant transfer passes. |
| **12. Unbounded Gas & Push-Payment Griefing** | Settlement, liquidation, or batch withdrawal loops over an attacker-growable array or pushes ETH/tokens to an attacker contract that reverts (`push` over `pull`), permanently bricking core protocol settlement. | Bounded pagination, pull-over-push claim pattern (`pendingWithdrawals[user] += amount`), or `try/catch` with gas cap isolating untrusted receiver failures. | Arm 1: Reverting receiver or dust-array growth causes `withdraw`/`liquidate` to revert out-of-gas or bubble revert for honest users. Arm 2: Honest users settle cleanly. Arm 3: Convert to pull accounting or bound iteration. Arm 4: Honest users settle cleanly even when attacker contract reverts. |
