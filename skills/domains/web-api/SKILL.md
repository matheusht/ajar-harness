# Domain Pack: Web, API, Service, and Supply-Chain Sinks

Load this pack only when `skill_mode=domain` on HTTP/REST/GraphQL/gRPC backends, web frontends, workflow engines, package/registry clients, or server-side model integrations.

**Step-2 Divergence Exit Rule:** Trace request data from route handler -> middleware -> service -> database/sink first. When you verify a real upstream guard (session-derived tenant scoping, parameterized query, contextual auto-escaping, or capability allowlist), stop immediately and close the task with `ajar task dry <task_id> --worker <id> --locus <file:line> --control "<reason>"`.

## Contrastive Pattern Matrix

### A. Authorization, Routing, and Workflow State

| Pattern | Defect Pattern & Sinks | Compensating Control That Makes It Safe | 4-Arm Verification Recipe |
| --- | --- | --- | --- |
| **1. Broken Object-Level Authorization (BOLA) & Client Selector Trust** | Handler looks up or mutates an object by `id` / `org_id` / `user_id` from path, query, JSON body, or header without binding the query `WHERE` clause or policy check to the authenticated session principal (`client-supplied-selector-authz`, `benchmarks/hermetic/targets/api-bola-state-change`). | Database query scopes lookup directly to `(id, session.tenant_id)` or RLS/policy middleware enforces ownership on the loaded entity, or object is intentionally public/shared across principals. | Arm 1: Principal B reads/mutates Principal A's private canary object. Arm 2: Principal A reads/mutates own object cleanly. Arm 3: Scope query/policy check to `session.principal_id`. Arm 4: Principal A request still succeeds while Principal B gets `403`/`404`. |
| **2. Legacy / Sibling Route & Unsafe-Default Authz Helper** | Canonical `/v2/` route enforces tenant/role checks while `/v1/`, `/internal/`, mobile, batch, webhook, or export sibling calls a shared helper whose authz binding is opt-in (`check_access(id, user=None)` defaults to allow when `user` is omitted; `legacy-route-differential`, `unsafe-default-authz-helper`). | Router-level default-deny middleware + mandatory non-optional principal parameter on every repository/service lookup across all route versions. | Arm 1: Unprivileged caller reaches resource via legacy/sibling route while canonical route denies. Arm 2: Authorized caller succeeds on both routes. Arm 3: Enforce principal binding in shared helper / legacy route. Arm 4: Authorized caller still succeeds. |
| **3. Function-Level (BFLA), Property-Level (BOPLA) & UI-Only Enforcement** | Admin/privileged action or sensitive model field (`role`, `is_admin`, `plan_tier`, `verified`, `price`) is hidden only in client UI (`ui-only-policy-enforcement`) while backend serializer binds raw request JSON into ORM model (`bopla-property-authz`, `broken-function-level-authz`). | Explicit server-side role middleware on privileged routes and strict request DTO allowlists excluding privileged columns (note: mere JSON echo without DB persistence is a false positive). | Arm 1: Unprivileged user persists guarded property or executes admin mutation (verified via subsequent state read). Arm 2: Standard profile/resource update persists allowed fields. Arm 3: Restrict DTO schema / add role guard. Arm 4: Standard update passes. |
| **4. GraphQL Global-ID, Nested Resolver & Batch Abuse** | Top-level query checks auth, while nested edge resolvers or Relay `node(id: base64("User:123"))` load records by decoded ID without re-checking tenant authorization (`graphql-abuse`, `api-graphql-global-id`). | DataLoader / model layer enforces viewer authorization inside every entity fetch regardless of traversal path (note: schema introspection or decoding an ID alone is not a finding). | Arm 1: Nested/node query by Tenant B returns Tenant A's private field canary. Arm 2: Tenant A's own nested query succeeds. Arm 3: Enforce viewer check inside entity loader. Arm 4: Tenant A's nested query passes. |
| **5. Business-Logic Race & Workflow Step Injection** | Coupon/withdrawal/quota check-then-act lacks `SELECT ... FOR UPDATE` / atomic conditional `UPDATE ... WHERE balance >= amt`, or durable workflow engine accepts unauthenticated/cross-tenant step replay/callback payloads (`business-logic-abuse`, `workflow-step-injection`). | Atomic single-statement conditional update / serializable transaction + HMAC/run-token-verified tenant binding on workflow step callbacks. | Arm 1: Concurrent requests overdraft balance or forge workflow step transition across tenants. Arm 2: Single authorized workflow/withdrawal succeeds. Arm 3: Enforce atomic conditional update / signed tenant step binding. Arm 4: Authorized workflow succeeds. |

### B. Injection, Server-Side Fetch, Protocol, and Supply-Chain Sinks

| Pattern | Defect Pattern & Sinks | Compensating Control That Makes It Safe | 4-Arm Verification Recipe |
| --- | --- | --- | --- |
| **6. SQL, Command, SSTI, XXE & Deserialization Sinks** | Untrusted input concatenates into raw SQL (`sql-injection`), `shell=True` / command-flag array (`os-command-injection`), template source string before compile (`server-side-template-injection`), XML parser with external entities enabled (`xxe-injection`), or `pickle`/`yaml.unsafe_load`/Java `ObjectInputStream`/PHP `unserialize` (`insecure-deserialization`). | Bound SQL parameters + allowlisted `ORDER BY` identifiers; `execFile`/`subprocess.run([...], shell=False)` with `--` separator; data passed as template context (never template source); `resolve_entities=False`/`disallow-doctype-decl`; safe JSON/typed schema parsers. | Arm 1: Payload alters SQL AST, executes benign canary command/template expression, reads local canary file via XXE, or instantiates gadget. Arm 2: Normal input executes cleanly. Arm 3: Parameterize / disable entity resolution / replace unsafe loader. Arm 4: Normal input passes. |
| **7. SSRF & Redirect-Follow Bypass** | Backend HTTP/webhook/media/import client fetches a user-supplied URL without blocking RFC1918/link-local (`169.254.169.254`)/loopback IPs at socket connect time, or validates initial URL then follows an HTTP `302` redirect to an internal IP (`ssrf-server-side-fetch`, `api-ssrf-redirect-follow`). | Custom DNS-pinning dialer resolves IP once, blocks private/loopback/metadata ranges on **every** redirect hop (or disables redirects), and restricts scheme to `https` (note: URL echo without server fetch is not SSRF). | Arm 1: Server fetches local/hermetic internal listener canary (directly or via `302` redirect). Arm 2: Fetch to allowed public fixture succeeds. Arm 3: Validate resolved IP per connect/redirect hop. Arm 4: Allowed public fixture fetch still passes. |
| **8. XSS, Transitive Sanitizer Reliance & Prototype Pollution** | User input renders via `dangerouslySetInnerHTML`/`v-html`/`innerHTML`/`javascript:` href (`cross-site-scripting`), sink assumes an upstream caller sanitized data while an alternate import/API write path bypasses the sanitizer (`transitive-sanitizer-reliance`), or recursive merge mutates `__proto__`/`constructor.prototype` (`prototype-pollution`). | Context-aware escaping at the **rendering sink** itself, URL scheme allowlist (`http:`/`https:`), and `Object.hasOwn` / blocking `__proto__`, `prototype`, and `constructor` keys during deep merge (note: escaped `&lt;script&gt;` text in source is inert). | Arm 1: Unescaped active markup/href executes in DOM sink or pollutes `Object.prototype` across requests. Arm 2: Plain/formatted text renders or merges cleanly. Arm 3: Sanitize/escape at sink or block prototype keys. Arm 4: Valid markup/merge passes. |
| **9. Path Traversal, Arbitrary File Upload & Cache/HTTP Smuggling** | Unnormalized filename reaches file read/write (`path-traversal-lfi`), uploaded SVG/HTML/executable is served same-origin with active MIME (`arbitrary-file-upload`), unkeyed header poisons CDN cache (`cache-poisoning`), or proxy/backend disagree on `Content-Length`/`Transfer-Encoding` (`http-protocol-abuse`). | Canonicalize path + `is_relative_to(base_dir)` with `O_NOFOLLOW`; serve uploads from isolated sandbox domain with forced-download `attachment` headers + `X-Content-Type-Options: nosniff`; include header in `Vary` or reject unkeyed host overrides. | Arm 1: Traverse outside root, serve executable same-origin upload, or poison cached response for clean victim request. Arm 2: Valid file access/upload/cached GET succeeds. Arm 3: Enforce canonical root / attachment header / cache key binding. Arm 4: Valid request passes. |
| **10. Registry / Lockfile Integrity Non-Enforcement (`Supply chain`)** | Package installer, plugin updater, or build fetcher downloads a tarball/artifact from a registry or mirror URL and extracts/executes it while ignoring missing or mismatched lockfile cryptographic digests (`registry-lockfile-integrity-nonenforcement`), or links a known-vulnerable dependency version with reachable vulnerable call path (`known-cve-exploitation`). | Strict SHA-256/SHA-512 integrity verification against pinned lockfile digest **before** decompression or execution, rejecting empty/downgraded checksums. | Arm 1: Modified tarball from mock registry with mismatched digest is extracted/loaded without error. Arm 2: Authentic tarball matching pinned lockfile digest installs cleanly. Arm 3: Verify SHA-256/512 digest prior to unpack and abort on mismatch. Arm 4: Authentic tarball installs cleanly. |

### C. Server-Side Model Output and Capability Dispatch Sinks

| Pattern | Defect Pattern & Sinks | Compensating Control That Makes It Safe | 4-Arm Verification Recipe |
| --- | --- | --- | --- |
| **11. `untrusted-model-output-sink`** | Application treats text or structured JSON returned by an LLM or external inference API as trusted and passes it unescaped into an active HTML/Markdown DOM sink (`dangerouslySetInnerHTML`), raw SQL query, shell command, template compiler, or unvalidated SSRF fetch (`benchmarks/hermetic/targets/llm05-render-escape`). | Model output is treated identically to untrusted user input: contextually escaped/sanitized at the HTML sink, bound via SQL parameters, and restricted from raw shell/eval execution. | Arm 1: Recorded/deterministic untrusted model output reaches active sink unescaped (`<img src=x onerror=...>` or SQL/command injection). Arm 2: Benign prose/Markdown model output renders cleanly. Arm 3: Escape/parameterize model output at sink. Arm 4: Benign prose/Markdown output renders cleanly. |
| **12. `client-controlled-tool-dispatch`** | Tool-router or action dispatcher executes a server-side capability (admin mutation, cross-tenant query, filesystem write, or internal API call) using a service-account credential without intersecting the tool call and its resource arguments against the **authenticated caller's** session permissions (`benchmarks/hermetic/targets/llm06-capability-dispatch`). | Tool dispatcher enforces caller-principal RBAC/ABAC and tenant scoping on both tool selection and every tool argument in deterministic server code (note: merely listing tool names in prose without executing the tool is not a finding). | Arm 1: Unprivileged caller session triggers execution of an ungranted tool or cross-tenant tool argument. Arm 2: Authorized tool call within caller's scope executes cleanly. Arm 3: Enforce session-principal capability + tenant check in dispatcher. Arm 4: Authorized tool call executes cleanly. |
