# Reference Corpus — False-Positive Traps, Compensating Controls & Triage Outcomes

Calibration corpus for `ajar ref query --kind precedent`, `skills/ajar-falsify/SKILL.md`, and `skills/ajar-report/SKILL.md`.
Use these verified counterexamples to reject unverified claims before reproduction and to avoid over-scoring partial primitives.

---

## 1. Compensating Controls That Invalidate Apparent Defects

Each row records a code or runtime shape that looks vulnerable on first inspection, the exact compensating control that makes it non-exploitable, and the condition that reopens the hypothesis.

| ID | Apparent Defect Shape | Compensating Control That Makes It Safe | Verification Check | Reopen Condition |
| --- | --- | --- | --- | --- |
| `FPC-01` | Crash/error serializer appears to leak internal error hints, cause chains, or credentials in JSON responses. | Outbound serializer uses a strict field allowlist rather than a regex blocklist, drops raw `message`/`hint`/`cause`, and stores internal state in ECMAScript `#private` fields so object spread, `Object.assign`, and `structuredClone` emit `{}`. | Trace every serialization hop from error construction to wire output and verify `Object.keys` / `JSON.stringify` on synthetic secret-bearing errors. | Any field that is type-gated rather than content-gated, or a custom serializer reading `#private` getters directly. |
| `FPC-02` | Library write-side or tree-side serializer (e.g., `JsonWriter`) lacks the recursion/nesting depth cap enforced on the streaming reader (`JsonReader` cap `255` vs stack limit `~6000`). | Every attacker-reachable ingest path parses untrusted bytes through the capped streaming reader before constructing the tree or invoking the writer. | Query `ajar ref query --kind reachability` for all callers of the uncapped API and verify whether any public entry point constructs deep trees without passing the capped reader. | Direct programmatic tree construction driven by attacker-controlled loop bounds or multi-message state accumulation. |
| `FPC-03` | Request payload carrying HTML/JS or template syntax appears verbatim in HTTP response body or chat output. | Output is serialized as inert text (`Content-Type: application/json` with `X-Content-Type-Options: nosniff`, framework text-node escaping, or URI scheme stripping of `javascript:`). | Assert actual DOM script execution or server-side expression evaluation (`{{7*7}}` -> `49`) rather than substring reflection. | Context switch into raw `innerHTML`, `dangerouslySetInnerHTML`, `document.write`, or server-side template `render(inline:)`. |
| `FPC-04` | Custom-domain or webhook validator accepts an internal or cloud-metadata IP literal (`169.254.169.254`) without throwing a validation error. | Server performs DNS lookup only or gates outbound HTTP fetch behind a prior CNAME ownership challenge that the attacker cannot satisfy on internal IPs. | Require an observed outbound HTTP connection (or reachable socket connect in source) before proposing an SSRF claim; DNS resolution alone is not SSRF. | HTTP client follows redirects (`301`/`302`/`303`/`307`) from an attacker-owned domain to `169.254.169.254` after passing initial validation. |
| `FPC-05` | Server echoes a client-supplied `model`, `role`, or `mandatoryTools` field in its JSON response or database preview. | Downstream execution router re-resolves allowed capabilities from the authenticated session token and ignores the echoed metadata field. | Verify execution effect (privileged tool actually invoked, restricted data returned) rather than echoed request parameters. | Dispatcher reads the client-supplied capability selector directly without intersecting against server-side principal policy. |
| `FPC-06` | Non-admin user receives `403 Forbidden` on `/api/admin/company/:companyId/*`, suggesting authorization works across the router. | Role check (`isAdmin`) and tenant binding (`user.companyId == params.companyId`) are distinct checks; a role-only helper (`validateAdmin(user)`) blocks non-admins while letting Tenant A's admin read/write Tenant B's company data. | Test cross-tenant isolation using two distinct accounts that both hold the required role in their own tenants (`Tenant A Admin` -> `Tenant B` resource). | Helper signature makes `expectedTenantId` optional (`validateCompanyAdmin(user, { expectedCompanyId? })`) and a call site omits the second argument. |
| `FPC-07` | SQL migration runs `REVOKE ALL ON FUNCTION fn FROM PUBLIC; GRANT EXECUTE ON FUNCTION fn TO service_role;`, making the `SECURITY DEFINER` RPC look locked down in the diff. | Default schema privileges (`ALTER DEFAULT PRIVILEGES ... GRANT EXECUTE ON FUNCTIONS TO anon, authenticated`) grant explicit role permissions that `REVOKE FROM PUBLIC` does not remove. | Test live `anon` / `authenticated` RPC invocation or inspect `information_schema.routine_privileges` rather than trusting `REVOKE FROM PUBLIC` in isolation; compare against a sibling RPC that checks `auth.uid()` in its body. | `SECURITY DEFINER` function lacks both explicit `REVOKE EXECUTE ... FROM anon, authenticated` and an in-body caller check. |
| `FPC-08` | Table metadata shows PostgreSQL Row-Level Security (`relrowsecurity = true`) enabled. | Permissive `CREATE POLICY` clauses combine with boolean `OR`; a single `FOR SELECT USING (true)` policy leaves the table world-readable to `anon` despite stricter sibling policies. | Read every policy expression on the table (`pg_policies`) and compare query rows returned to `anon` against a restricted sibling table. | Permissive policy lacks `auth.uid()` or tenant-membership predicate on non-public tables. |
| `FPC-09` | Internal microservice or backend parser exhibits Host-header routing confusion or unsafe `eval()` on a downstream field. | Canonicalizing reverse proxy rewrites `Host` and normalizes headers on every external request, or the upstream bridge forwards only a hardcoded literal payload where no attacker-controlled bytes ride. | Trace both (a) service reachability from the external boundary and (b) end-to-end taint from attacker input into the downstream sink; record isolated internal behaviors with `ajar primitive add` instead of filing unconfirmed external RCE. | Alternate ingress route, direct port exposure, or secondary parameter that injects bytes into the bridge request. |
| `FPC-10` | Cookie `csrftoken` can be omitted or modified in a state-changing POST without causing an error when `X-CSRFToken` header matches, or vice versa. | Framework uses `csrftoken` cookie only as a JavaScript read helper while validating a separate signed session-bound anti-CSRF token in form body or custom header (`X-CSRFToken`). | Remove all anti-CSRF headers/fields simultaneously from a cross-origin request context before claiming CSRF protection bypass. | Endpoint accepts simple `application/x-www-form-urlencoded` / `text/plain` POSTs with cookies alone and skips token verification. |
| `FPC-11` | Code adjacent to a historical CVE uses an unusual custom parser or sanitizer. | Post-CVE hardened paths often enforce strict canonicalization or structural bounds; meanwhile legacy sibling endpoints (`/v1/`, widget/sync/import routes) omit the new guard entirely. | Diff canonical vs. legacy/bulk/sync routes serving the same underlying model (`legacy-route-differential`). | Legacy route or batch sync endpoint mutates the entity store directly without calling the controller guard. |
| `FPC-12` | Multi-pass string sanitizer strips `"../"` or `"<script>"` once in fixed order (`replace("../", "")`). | Single-pass removal is NOT a valid control when nested payloads (`"....//"`, `"<scr<script>ipt>"`) reconstitute the forbidden token after pass 1; conversely, post-sanitization canonical path prefix check (`realpath` + `startsWith(baseDir + "/")`) IS a valid control. | Check whether enforcement happens after final canonicalization/decoding or relies on single-pass substring deletion. | Validation runs before URL decoding, Unicode normalization, or path resolution. |

## 2. Disclosed Bug-Bounty False-Positive & Non-Qualifying Precedents

Real public HackerOne reports closed as `Informative`, `Not-Applicable`, or `Duplicate` — use these during `ajar-falsify` to kill non-vulnerabilities early.

| Report | Triage Outcome | Claimed Class | Why Triagers Rejected the Claim | Rule for `ajar-falsify` |
| --- | --- | --- | --- | --- |
| [H1-50537](https://hackerone.com/reports/50537) | Informative | SSRF | Outbound macro URL fetch reached no sensitive internal service and returned no protected metadata. | Blind/open URL fetch without internal boundary crossing or data/state impact stays a `primitive`, not a High SSRF finding. |
| [H1-163501](https://hackerone.com/reports/163501) | Informative | Email Spoofing (CWE-290) | Missing SPF/DKIM/DMARC DNS records without an application-logic authentication defect. | Do not propose claims on DNS mail-authentication records alone. |
| [H1-261817](https://hackerone.com/reports/261817) | Informative | Info Disclosure (CWE-200) | Public client JavaScript bundle exposed non-secret configuration constants and public keys (`anon` keys, public endpoints). | Public client bundles and documented public keys (`anon` key, OAuth `client_id`) are not secrets unless paired with missing backend authorization. |
| [H1-294568](https://hackerone.com/reports/294568) | Duplicate / None | Info Disclosure (CWE-200) | Publicly readable `composer.lock` dependency versions without an exploitable vulnerable dependency sink. | Dependency version disclosure alone confers zero exploit capability. |
| [H1-348801](https://hackerone.com/reports/348801) | Informative | Banner Disclosure | Server HTTP header disclosed Apache version string without an unpatched vulnerability. | Never propose version-banner disclosure claims. |
| [H1-675398](https://hackerone.com/reports/675398) | Not-Applicable | CSRF Bypass | Reporter omitted the JS-helper cookie while still sending the valid `X-CSRFToken` header; real CSRF check held. | Verify negative control by stripping the actual enforcement token, not auxiliary delivery cookies. |
| [H1-832593](https://hackerone.com/reports/832593) | Informative | Clickjacking (CWE-1021) | Missing `X-Frame-Options` on a static/read-only page with zero state-changing actions. | Never file missing framing headers unless framing hijacks a concrete sensitive state-changing action. |
| [H1-1316412](https://hackerone.com/reports/1316412) | Not-Applicable | Directory Listing | `/static/` directory listing exposed only public CSS, JS, and font assets. | Static asset directory listing without sensitive private files is intended behavior. |
| [H1-1340650](https://hackerone.com/reports/1340650) | Not-Applicable | Rate Limiting | Unthrottled password-reset email trigger without token leakage or account takeover. | Rate-limit absence without brute-forceable short secrets (`<= 6` digits) or financial/state corruption is non-qualifying. |
| [H1-1712240](https://hackerone.com/reports/1712240) | Not-Applicable | SSRF Mislabel (CWE-918) | Server returned HTTP 200 when sent an attacker `Referer` header, without making any server-side outbound request. | Never confuse header reflection or permissive parsing with server-side outbound request forgery. |
| [H1-2588810](https://hackerone.com/reports/2588810) | Informative | TOTP Window > 60s | Accepting a recently expired 6-digit TOTP token within a clock-skew window still requires valid primary credentials and resists brute force. | Extended TOTP skew windows (`60–180s`) are standard clock-drift tolerances unless rate limits allow full keyspace exhaustion inside the window. |
| [H1-2979176](https://hackerone.com/reports/2979176) | Not-Applicable | Public API Data | Unauthenticated endpoint returned public creator statistics intentionally displayed on public profile pages. | Compare API fields against unauthenticated UI views (`intent` check) before claiming unauthorized disclosure. |

## 3. Severity Downgrade & Containment Calibrations

Disclosed cases where a real vulnerability reproduced, yet vendor triage scored lower than the reporter's headline claim because of concrete preconditions or containment boundaries.

| Report | Claimed Framing | Verified Triage Outcome | Narrowing Factor | Rule for `ajar-report` |
| --- | --- | --- | --- | --- |
| [H1-341876](https://hackerone.com/reports/341876) | Root access across all instances | Resolved — Medium (`6.9`) | Liquid SSRF leaked GCP metadata token on isolated review sandbox instances, while metadata write escalation was blocked. | Score the compromised component's actual blast radius and isolation boundary, not production fleet assumptions. |
| [H1-422944](https://hackerone.com/reports/422944) | Critical RCE on core platform | Resolved — Medium | ImageTragick RCE ran inside isolated subsidiary infrastructure (`Kit`) with zero access to core production data. | Check service/container isolation before assigning `Scope: Changed` (`S:C`) or Critical severity. |
| [H1-546753](https://hackerone.com/reports/546753) | Critical OS Command Injection | Resolved — High (`8.4`, `PR:H/UI:R`) | Archive filename command injection (`CVE-2019-5441`) required both high privileges (`PR:H`) and user interaction (`UI:R`). | Encode exact `PR` and `UI` preconditions in CVSS vectors instead of defaulting RCE to `9.8`. |
| [H1-810880](https://hackerone.com/reports/810880) | Zero-click full Account Takeover | Resolved — Medium | Unbound `/api/2fa` enrollment worked only against victim accounts that had not yet enabled 2FA. | Document victim-state preconditions (`2FA disabled`, `empty vault`, `non-default config`) explicitly; they lower `AC` or severity tier. |
| [H1-1114347](https://hackerone.com/reports/1114347) | Account Takeover | Resolved — Low (`3.7`, `AC:H/PR:L/UI:R`) | Stale email-change link required high attack complexity, prior access, and victim interaction. | Never label constrained session/link edge cases "full ATO" when `AC:H` and `UI:R` apply. |
| [H1-1323406](https://hackerone.com/reports/1323406) | Massive data loss via IDOR | Resolved — Medium | Checkout parameter swap (`checkout_ari`) exposed order PII (`C:L/I:N/A:N`) without write or takeover capability. | Read-only single-record PII IDOR typically scores Medium (`4.3–6.5`), not Critical. |
| [H1-2528293](https://hackerone.com/reports/2528293) | Exposes all ML models | Resolved — Medium (`4.3`, `PR:L/C:L/I:N/A:N`) | Sequential ID walk read model metadata across projects without write access or secret exfiltration. | Distinguish metadata confidentiality (`C:L`) from full secret/credential read (`C:H`). |
| [H1-3154983](https://hackerone.com/reports/3154983) | Critical arbitrary account deletion | Resolved — High | Replaying victim `email` + `authPW` on `/v1/account/destroy` lacked session binding, but required prior capture of `authPW`. | Unbound destructive endpoints that still require a hard-to-obtain victim artifact are High (`AC:H`), not unconditional `9.8` Critical. |
| `XBEN-056` | SSTI -> full secret exfiltration | Primitive confirmed; escalation blocked | Template expression evaluation (`{{7*7}}`) fired, but Django 4.2.13 blocked underscore attribute traversal (`settings.SECRET_KEY`). | Confirm base injection and post-injection gadget chains separately; never infer RCE from `{{7*7}}` alone. |
